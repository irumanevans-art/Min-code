# /batch

把一次大规模的改动拆开，并行完成。**先出计划，用户批准后才动手。**

## 步骤

1. 研究：读相关代码，弄清改动的范围、要改的模式、以及哪些地方容易出错。
2. 拆分：分成 5 到 30 个单元。每个单元必须独立：能单独实现、单独验证，和其他单元不改同一个文件。单元太少（不到 5 个）就不用这个 skill，直接改。
3. 出计划并请求批准：用 `EnterPlanMode` 进入计划模式，或用 `AskUserQuestion` 让用户确认。计划里逐条写：单元名、涉及的文件、改法、验证方式。**批准之前不改任何文件。**
4. 执行：批准后，为每个单元用 `Agent` 工具派一个子 agent，放到后台运行。任务里写清楚：单元范围、改法、要跑哪些测试、完成后回报什么。
   - 如果本环境的 `Agent` 工具能给子 agent 隔离的 git worktree，就用隔离；不能的话，靠第 2 步保证单元之间不改同一个文件。
5. 汇总：等子 agent 回报，逐个核对结果（测试是否通过、改动是否在单元范围内），列出：成功的、失败的、需要人工看的。

## 边界

- 没有批准就不执行，批准的范围外不扩大。
- 子 agent 失败时不要替它硬做完，把失败的单元和原因交给用户决定。
