# /simplify

对改动做一轮清理，然后应用修改。这一轮只看质量，不找正确性问题。

## 步骤

1. 确定范围：没有参数时用 `git diff` 取当前改动；有参数时只看参数指定的路径或 PR。
2. 并行派出四个只读的子 agent（用 `Agent` 工具，在同一条回复里一起发出），每个只负责一个角度：
   - 复用：有没有已有的函数、工具类或库能替代新写的代码。
   - 简化：有没有不必要的分支、重复、包装层或过度抽象。
   - 效率：有没有多余的循环、重复的 IO、不必要的分配或拷贝。
   - 抽象层级：改动放的位置对不对，有没有越过本该属于的层。
   每个子 agent 的任务里写清楚：要看哪些文件、只回报具体的改法（文件、行、怎么改、为什么），不要改文件。
3. 收齐四份结果后，自己判断每条建议是否成立。成立的直接修改；拿不准的不改，原样列在最后。
4. 修改后跑相关的已有测试（如果容易跑），确认行为没有变化。
5. 汇报：改了哪些、为什么；不改的列出来，说明理由。

## 边界

- 不改行为。清理的目的是让代码更短、更清楚、更便宜，不是换一种做法。
- 不做与改动无关的重构。
