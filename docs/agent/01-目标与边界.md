# 01 · 目标与边界

## 一句话

**Min Agent**：长在 Min 里的 agent 内核。纯 Kotlin/JVM，随 App 启动即用；文件工作在宿主侧直接做，
只有 shell 进 proot；会话以事件日志为唯一事实来源，进程随时被杀都能从断点接着跑；
国产模型和 Anthropic / OpenAI 一样是一等公民。Claude Code 有的内核能力全部对标，在手机上做得更好。

## 为什么要自研（现状的天花板）

Min 现在是「在 proot 里跑别人的 CLI，再从它的输出流里猜状态」。这条路已经走到头了，证据都在仓库里
（摘要见 00-调研综述.md §4；原调研报告未入库）：

| 天花板 | 实测 / 证据 |
|---|---|
| 协议是猜的 | CLI 适配层 77 条代表性补丁，横跨 CLI 2.1.246–2.1.283 共 11 个版本：形状猜测 18、版本漂移 13、功能缺口绕行 24、竞态 13 |
| 功能够不着 | 改 effort / 上下文窗口 / 缓存 TTL 都要重启 Node（4–8 s）；给子 agent 说话只能借 hook 回调旁路；撤销只回文件、回不了对话；花费从文本里抠 |
| 资源太重 | 每会话一个约 200–220 MB 的 claude 进程（实测，另有 App 本体 188 MB），同时最多 3 个会话；rootfs 装好 533–550 MB，装完才能用 |
| proot 里的文件操作慢 | 实测遍历慢 37 倍、读小文件慢 50 倍、grep 慢 26 倍（起进程不慢）；CC 在 Linux 上的搜索全走 Bash，正好落在最慢的路上 |
| 国产模型二等 | 只会说 Anthropic 协议，其余靠本机 relay 转：丢 `reasoning_content`（DeepSeek / Kimi 工具循环里不回传直接 400）、流式 `input_tokens` 恒 0、tool_choice 映射错 |
| 安全面在别人手里 | token 只能走环境变量（`/proc/<pid>/cmdline` 可读）；危险命令判定是 CLI 的，Min 只能在外面补正则 |
| 被杀即丢 | 会话状态在 Node 进程里，App 进程一死，半截回合、排队消息、待审批全丢 |

## 目标

1. **满血对标**：Claude Code 的全部**内核能力**（工具、权限与模式、hooks、记忆、子 agent 与团队、工作流、skills / plugins / MCP、
   会话 / checkpoint / rewind、上下文与缓存、定时与后台任务、输出样式……）都有，行为语义对齐，能直接读用户现成的
   `.claude/`、`CLAUDE.md`、`AGENTS.md`、`.mcp.json`、插件。逐项见 05-对标清单.md。
2. **为 Min 而生**：
   - 进程随时被杀 → 任意点恢复，不丢输入、不重跑副作用、不重复扣费。
   - proot 慢 → 文件读写、搜索、diff、git 快照都在宿主侧做；shell 复用环境快照；不 fork 就能做的事不 fork。
   - 触屏 → 审批三键（本次 / 总是 / 拒绝并附言），通知上直接批；计划、提问、进度都是卡片。
   - 手机能力 → 设备控制、截图、通知、分享、剪贴板、预览槽是内核原生工具，不绕 MCP-over-HTTP。
   - 流量与电量 → 提示缓存命中率是头号指标；后台反思只在充电 + 不计流量时跑。
3. **多供应商卓越**：Anthropic Messages、OpenAI Chat、OpenAI Responses、Gemini 四套线协议原生实现；
   DeepSeek、GLM、Kimi、Qwen、MiniMax、豆包按各自怪癖表正确处理推理回传、缓存、工具调用、溢出报错。
   按模型族配 harness profile（编辑工具形态、提示词、工具集）。便宜模型干活、贵模型当顾问（Oracle）。
4. **可维护性在高位**：模块边界由构建系统强制；每个包 README 固定写「模型看到什么 / token 代价 / 缓存影响 / 已知限制」；
   协议与持久化格式有版本纪律；每一处提示词改动都有请求快照测试兜住。

## 非目标（明确不做）

| 不做 | 理由 |
|---|---|
| **用 Claude 订阅驱动 Min Agent** | Anthropic 条款禁止第三方 harness 使用订阅凭证；也违背 Min「不碰凭证」的铁律。订阅用户继续走官方 CLI 引擎，那条路**冻结维护、不删** |
| **伪装成 Claude Code / Codex 发请求** | pi-ai 的 "Stealth mode" 这类做法一律不做；User-Agent 如实写 Min |
| Anthropic 云端 / 企业专属能力 | Remote Control、claude.ai 云会话、Slack、Claude Tag、GitHub Actions、managed / server-managed settings、analytics、gateway、routines 云端部分——不对标；其中对手机有意义的做**本地等价物**（见 05） |
| 终端 UI 专属能力 | keybindings、vim 模式、fullscreen、terminal-config——Min 有自己的界面 |
| 内核进程内运行第三方代码 | hooks、MCP server、插件的可执行部分一律进程外（proot 或网络）；内核只加载自己的代码 |
| 动态插件框架 | DeepSeek Harness 的教训：缺依赖静默不加载、组合层静默失效，100% 单测覆盖也没拦住。Min 用 Kotlin 接口 + 构造注入，编译期可见 |
| 抄泄露源码 | 只参考公开分析里的架构描述，不下载、不阅读、不引用泄露代码；Min 是公开 AGPL 仓库，保持 clean-room |
| 照搬 Codex / CC 的沙箱实现 | Android 上没有 bubblewrap（无 user namespace）和 Landlock（内核未编入），实测确认；Min 自建隔离层：seccomp（禁网、禁危险调用，硬）+ 自维护 proot 的路径策略（防误操作级）+ 宿主判定与回滚，逐层如实标注强度（04 §4.4.1） |

## 硬约束

- **Android**：minSdk 26 / targetSdk 37；只能从 nativeLibraryDir 执行二进制（W^X）；全系统 phantom 子进程上限 32；
  前台服务以 specialUse 为主，dataSync 在 Android 15+ 后台 24 小时限 6 小时。
- **proot**：ptrace 实现，fork/exec 与文件系统调用都慢；SIGTERM 杀不死 proot，要用 `ProcessTreeKill.reap`；
  SELinux 禁读一批 `/proc`。
- **凭证**：API key 只在 Keystore 与内核的 HTTP 客户端之间流动，**永不进入 rootfs、环境变量、命令行、日志**。
  这一条比现在的 CLI 方案严格（现在 token 在 CLI 的 env 里，模型的 Bash 理论上读得到）。
- **中转与隐私**：会话日志永不随请求上传（DeepSeek Harness 默认把增量日志塞进请求、中转也能收到，Min 不做）；
  本机监听的任何端口只绑 127.0.0.1、带随机 token、校验 Origin（OpenClaw 网关被网页一键劫持的教训）。
- **许可证**：Min 是 AGPL-3.0。可以吸收 MIT / Apache-2.0 代码（需署名进 NOTICE）；Crush（FSL）只借思路；
  泄露代码零接触。

## 成功标准（每个里程碑都拿这几条量）

| 指标 | 怎么量 | 目标 |
|---|---|---|
| 恢复正确率 | 桌面恢复测试：在事件流的随机点杀进程 → 重启 → 续跑，比较日志与请求 | 100%：不丢输入、副作用不重放、请求可从日志逐字节重建 |
| 首 token 时延 | 发送到第一个字出现（同模型同网络，对比 CLI 引擎） | 内核自身开销低于 CLI 基线（模拟器实测 CLI 约 0.46 s）；改 effort / 模型不再有 4–8 s 的重启 |
| 常驻内存 | 单会话 / 三会话 PSS | 每多一个会话的边际内存远低于 CLI 的约 200 MB |
| 文件类工具时延 | 同一批 Read / Glob / Grep 操作 | 接近宿主侧实测值，而不是 proot 内的 26–50 倍 |
| 缓存命中率 | usage 里的 cache read / 总输入 | Anthropic 与国产自动缓存的长会话 ≥ 80% |
| 任务成功率 | 桌面评测集（按模型分列），与同模型下的 Claude Code / Codex 对比 | 同模型不低于对手；国产模型显著高于「CLI + relay」 |
| 对标完成度 | 05-对标清单.md 的勾选率 | 按里程碑推进，M5 结束时内核能力 100% |
