# 02 · 总体架构

## 1. 全景

```
┌────────────────────────── Min App（dev.min.code，Android）──────────────────────────┐
│                                                                                    │
│  UI（Compose，海/云/陶）                                                            │
│    └─ SessionVM（引擎无关，按能力位显隐控件）                                        │
│         └─ Engine SPI：Engine / EngineSession / EngineCapabilities                  │
│              ├─ MinAgentEngine      ←── 本设计的主角（进程内）                        │
│              ├─ ClaudeCodeCliEngine ←── 现有 CLI 适配层，冻结维护（Claude 订阅唯一路） │
│              ├─ CodexEngine         ←── 现有 app-server 适配层                        │
│              └─ AcpEngine（M6）     ←── 任意 ACP agent（Gemini/Kimi/OpenCode…）       │
│                                                                                    │
│  宿主适配（agent 端口的 Android 实现，app/…/core/engine/min/host/）                  │
│    RootfsFileSystem(PathMapper) · ProotExecutor(ShellSnapshot) · NativeSearch(rg)   │
│    · ApprovalBridge(卡片+通知) · DeviceTools · Notifier · KeystoreSecrets            │
│    · AndroidScheduler(WorkManager/闹钟→FGS) · ShadowGit(JGit) · OkHttpTransport     │
│                                                                                    │
└───────────────────────────────────────┬────────────────────────────────────────────┘
                                        │ 只经过 agent-protocol 的类型（可序列化）
┌──────────────────────────── Min Agent 内核（纯 Kotlin/JVM，agent/ 下）──────────────┐
│  protocol  线协议类型：Command / Event / Item / Snapshot / 错误码 / 版本              │
│  spi       端口接口：ModelTransport、Workspace(Fs/Exec/Search)、Approvals、Clock…    │
│  kernel    会话 actor、turn 状态机、工具调度、恢复、上下文装配的编排                  │
│  llm       四套线协议编解码 + 供应商怪癖表 + 模型目录 + 用量/花费                     │
│  tools     内置工具（文件/搜索/编辑/shell/web/计划/提问/任务/子 agent/定时…）         │
│  policy    权限规则、模式、路径分级、命令分析、auto 审查、安全底线                      │
│  context   提示装配、记忆文件、压缩流水线、缓存规划、循环检测                          │
│  ext       Claude Code 兼容生态：settings/hooks/agents/commands/skills/plugins/MCP    │
│  store     事件日志(JSONL) + 快照 + 索引(SQLite) + 大输出落盘 + checkpoint 接口       │
│  testkit   脚本化假模型、SSE 录放、假宿主、请求快照、随机杀进程的恢复测试              │
│  cli       桌面 JVM 宿主：开发、评测、录夹具（不进 APK）                               │
└────────────────────────────────────────────────────────────────────────────────────┘
        │ Bash / hooks / MCP stdio server / 插件可执行部分
        ▼
  proot Ubuntu rootfs（可选的「Linux 工具箱」：没装也能用文件、问答、设备类能力）
```

**三条总纲**

1. **日志即真相**：会话的一切（模型看到的、做过的、被批准的）都是追加写的事件；内存状态只是日志的折叠结果。
   任何时刻杀进程，重启后折叠日志就回到同一状态，下一次模型请求能从日志**逐字节**重建。
   五家（DeepSeek Harness、pi、OpenCode V2、OpenHands、Goose）独立收敛到这一点，不再讨论。
2. **宿主做重活，proot 只跑 shell**：读写、搜索、diff、快照、MCP HTTP、网络请求都在 App 进程里做；
   只有「必须是 Linux 进程」的东西（用户的命令、hooks、stdio MCP server）进 proot。
3. **边界编译期可见**：模块依赖由 Gradle 强制、端口是窄接口、组合在一个地方用构造注入完成。
   不做运行时插件发现，不做反射注册。

## 2. 模块与依赖规则

目录：仓库根下新建 `agent/`，每个子目录一个 Gradle 模块（`settings.gradle.kts` 里 `include(":agent:kernel")` 这样）。
除 `cli`（JVM application）外全是纯 Kotlin/JVM 库（`kotlin("jvm")`，JVM 17，与 app 同一套 Kotlin / 协程 / serialization 版本）。

| 模块 | 职责（一句话） | 允许依赖 | 第三方依赖 |
|---|---|---|---|
| `:agent:protocol` | UI↔内核的线协议类型与版本 | — | kotlinx.serialization |
| `:agent:spi` | 内核对外部世界的全部端口接口 + 共享的值类型 | protocol | 协程 |
| `:agent:store` | 事件日志、快照、索引、大输出、会话目录布局 | spi | androidx.sqlite（driver 接口） |
| `:agent:llm` | 规范消息模型、四套编解码、怪癖表、模型目录、用量花费、重试 | spi | OkHttp（仅在 transport 实现里） |
| `:agent:policy` | 规则解析与求值、模式、路径分级、命令分析、auto 审查编排 | spi | （tree-sitter 通过 spi 端口注入） |
| `:agent:context` | 提示装配、记忆发现、压缩流水线、缓存规划、循环检测 | spi, llm(只用规范消息类型) | — |
| `:agent:tools` | 内置工具实现（只用 spi 端口，不碰真实文件系统） | spi, policy(只用判定结果类型) | java-diff-utils |
| `:agent:ext` | CC 兼容配置发现与加载、hooks 执行编排、skills/agents/commands/plugins、MCP 客户端 | spi | MCP kotlin-sdk-client（包一层） |
| `:agent:kernel` | 会话 actor、turn 状态机、工具调度、恢复、子 agent、工作流、组合根 | 以上全部 | 协程 |
| `:agent:host` | 宿主侧端口的纯 JVM 实现：rootfs 文件系统（按 guest 根解析符号链接、bind mount、越界拒绝）等；桌面 CLI 与 Android 宿主共用 | spi | — |
| `:agent:testkit` | 测试替身与夹具工具 | kernel 及以下 | JUnit |
| `:agent:cli` | 桌面宿主 | kernel, host, testkit(录制) | — |
| `app`（`core/engine/min/`） | Android 宿主适配 + 引擎 SPI 实现 | kernel, protocol | 现有 |

**铁律**（M0 用一个架构测试把它们钉住，违反即红）：

- `agent/*` 任何模块**不得**依赖 `android.*`、`androidx.*`（`androidx.sqlite` 的纯接口例外）、`dev.min.code.*`。
- 只有 `kernel` 能看到所有模块；其余模块之间只能按上表单向依赖，不许环。
- 真实 IO（文件、进程、网络、时钟、随机数）只能出现在宿主实现与 `cli` 里；内核模块只通过 `spi` 端口触达。
  这保证桌面 JVM 能用同一套内核跑评测，也保证恢复测试可以控制时间和随机性。
- UI 只认 `protocol`，不认 `kernel` 的内部类型。今天是进程内直调，明天换成 `:engine` 独立进程只换传输，不改 UI。

## 3. 进程与线程模型

- **一期：进程内**。内核跑在 App 进程，自己的协程作用域和调度器（IO 用 `Dispatchers.IO` 的受限视图，
  CPU 活用 `Dispatchers.Default`）；前台服务（specialUse）在有活跃回合 / 后台任务时持有。
- **二期可选：`:engine` 独立进程**（同一 APK 的 `android:process`）。收益是 UI 崩溃不带走内核、堆分开；
  代价是 IPC 与设置跨进程。因为 UI 只经过 `protocol`，切换只是把传输从直调换成 Binder / 本机 socket 上的同一份 JSON。
  触发条件：M2 真机数据显示 UI 侧崩溃或内存压力确实威胁到会话。
- **每个会话一个 actor**：`SessionActor` 独占该会话状态的修改权，所有命令进它的单消费者队列（Codex 的 SQ 模型）。
  每个 turn 是 actor 下的一个子 Job；工具执行、模型流式是 turn 的子 Job。会话级 `SupervisorJob`。
- **取消纪律**：清理用 `withContext(NonCancellable)`；禁止用 `runCatching` 包挂起调用（会吞 `CancellationException`，
  Min 现有代码里很多）——统一用 `spi` 里的 `catchingNonCancellation {}`，由 lint 规则或架构测试禁用前者。
- **子进程预算**：全系统 phantom 子进程上限 32（模拟器上实测未触发，真机待测，仍按上限保守设计）。内核维护一个进程配额（默认会话 shell 1 个 + 后台任务上限 + MCP stdio 上限），
  超额排队并在 UI 上说明，而不是被系统悄悄杀掉。

## 4. 数据流：一次回合

```
UI ──Command.SendInput(clientMsgId, expectedTurnId?)──► SessionActor
  1. 写 InputReceived 到收件箱（fsync）→ 回 Ack（幂等：同 clientMsgId 只收一次）
  2. 到安全点（无回合在跑，或当前工具批结束）→ InputPromoted（成为正式用户消息）
  3. TurnStarted → 上下文装配（稳定前缀 + 历史投影 + 末尾追加的世界状态增量）
  4. ModelRequestStarted(requestId, 前缀指纹)（fsync）→ transport 流式
       ├─ 瞬时流：TextDelta / ThinkingDelta / ToolInputDelta（不落盘，只推 UI）
       ├─ 分段落盘：AssistantSegment（按 1s / 4KB 攒批，用于崩溃后展示半截）
       └─ 工具调用块完整 → 立即进调度器（流式中提前执行只读、并发安全的工具）
  5. 每个工具：ToolPlanned → 权限管线（hooks→规则→模式→路径分级→命令分析→审查/人）
       → ToolEffectPending（fsync，副作用前的最后一步）→ 执行 → ToolOutcome（fsync）
  6. 模型本轮结束 → AssistantMessageCompleted(usage, stop)；有工具结果则回到 3，否则
  7. TurnCompleted(用量、花费、耗时、终止原因) ——或 TurnFailed / TurnInterrupted
UI ◄── 持久事件流（带 seq，可从任意 seq 续传）+ 瞬时流（打字增量，不保证重放）
```

## 5. 恢复（进程被杀之后）

启动时对每个「最后状态不是终态」的会话做一次恢复折叠：

| 日志停在 | 恢复动作 |
|---|---|
| InputReceived 未 Promoted | 保留在收件箱，照常在安全点提升（输入永不丢） |
| ModelRequestStarted，无后续 | 本次请求无副作用，标记 `interrupted`，已落盘的 AssistantSegment 作为「被中断的回答」给 UI 看；是否把半截写进模型历史按供应商 profile 决定（默认写入并注明中断） |
| ToolPlanned / 等审批 | 审批请求重新挂到 UI（审批是持久事件，不是内存回调） |
| ToolEffectPending，无 Outcome | 按工具声明的 `resumePolicy`：`Replay`（只读工具）直接重跑；`Reattach`（后台 shell 有 pid + 日志路径）重新挂上；`Unknown`（其余）合成结果「执行被中断，结果未知，不要盲目重试有副作用的操作」并附最后的输出快照 |
| 回合中途，工具都有结果 | 发请求前自动补齐缺失的 tool result（确定性合成 id），历史一定合法，缓存前缀不断 |

恢复后**不自动继续跑**，除非该会话处于用户明确开启的「自治」状态（goal / loop / 工作流）；否则在 UI 上显示
「上次中断于……」卡片，由用户点继续。这条是手机场景的安全默认。

## 6. 协议：UI ↔ 内核（Min Agent Protocol，MAP）

形状取 Codex app-server v2 的 thread / turn / item 三层，外形对齐 ACP v2（为 M6 对外暴露 ACP 留路）：

- **命令**（UI→内核）：都带 `commandId`（幂等键）；改动当前回合的带 `expectedTurnId`，过期即拒并说明原因。
  例：`SendInput`、`Steer`（插话，下个安全点送达）、`Interrupt`、`AnswerApproval`、`AnswerQuestion`、`SetMode`、
  `SetModel`、`SetEffort`（**热切，不重启任何进程**）、`Rewind(toItemId, scope=代码|对话|两者)`、`Fork`、`Compact`……
- **持久事件流**（内核→UI）：`seq` 单调递增；UI 订阅时给 `fromSeq`，内核先补历史再接实时（先登记监听再补，不丢事件）；
  `item.completed` 永远带完整终态，UI 丢了中间片段也能自愈。
- **瞬时流**：打字、思考、工具参数的增量，只为观感，丢了无所谓。
- **快照**：`SessionSnapshot`（ID 键控的覆盖式状态：items、待审批、任务、子 agent 树、用量），断线重连 = 快照 + 之后的事件。
- **服务端请求**：审批、提问、计划确认都是内核发给 UI 的请求（带 thread/turn/item 三级 id），另有「已被处理」通知，
  通知栏和界面两边谁先答算谁，另一边自动收起（channels 的「先到者生效」）。

这一层就是 Min 现在「hook 答复错投到新进程」「排队消息被吞」「子 agent 收件箱竞态」这一族 bug 的根治：
它们全是「从别人的输出流猜状态」的产物，MAP 里状态由内核声明、由 seq 保序。

## 7. 与现有 Min 的接缝

| 现有组件 | 去向 |
|---|---|
| `core/session/ChatItem`（引擎无关的渲染模型） | 保留，演进为 MAP `Item` 的 UI 投影；由各引擎适配器填充 |
| `ClaudeCodeManager.SessionState` + VM 直调 25 个方法 | 抽出 `EngineSession` 接口（M2），`ClaudeCodeVM` 泛化为 `SessionVM`，按 `EngineCapabilities` 显隐控件 |
| `ClaudeCodeManager` 及 CLI 适配层 | 冻结维护，只修 bug，不再加功能（Claude 订阅用户的唯一路） |
| Codex 适配层 | 保留，接到同一个 `EngineSession` |
| `core/relay`（Anthropic↔OpenAI 转换，约 1500 行） | 作为 `agent:llm` 的 openai-chat 编解码起点，先修三处已知缺陷（丢 reasoning_content、流式 input_tokens=0、tool id 往返）；CLI 引擎继续用旧 relay 直到它退役 |
| `AgentServiceHost` / LocalServiceRegistry / BackgroundShells | 复用：后台 shell 与托管进程表直接成为 `Exec` 端口的后台任务实现 |
| `DeviceController` 等（7 个设备工具） | 改为内核原生工具，不再经 MCP-over-HTTP；DeviceMcpServer 保留给 CLI 引擎 |
| `ClaudeCodeCheckpointStore` | Min 会话由宿主侧内容寻址快照仓库取代（覆盖 Bash 改动，见 `detail/检查点与rewind设计.md`）；CLI 引擎继续用旧的 |
| CostLedger、ComposerDraft、SessionMeta、GuestOpen、预览槽、FGS、通知 | 复用，数据源换成 MAP 事件 |
| `guestToHostFile` / `resolveRootfsPath`（两份不一致的路径映射） | 合并为一个 `PathMapper`（按 guest 根解析符号链接、认 bind mount、处理 `.l2s.`），先写测试 |
| 供应商 DataStore（事实来源） | 原则不变；方言枚举升级为 `ProviderDescriptor`（线协议 + 怪癖 profile + 端点 + 鉴权方式） |
