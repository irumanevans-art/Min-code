# 网络域名批准设计

日期：2026-10-08。状态：草案，依据 M5 总览第四节决定 5（**做**，逐域名界面批准）。

CC 的对应做法（`D:\kimi\workspace\research\inventory\raw\mcp\cc-settings-reference.md` 第 768–777 行）：沙箱里的命令只能访问 `sandbox.network.allowedDomains` 列出的域名；未列出的会弹出批准；`deniedDomains` 即使在通配里也拦；`allowManagedDomainsOnly` 可把名单锁给托管设置。

## 一、要解决什么

Min 里模型能跑的命令（Bash，在 proot 里）能联网。网络出口是数据外泄的主要路径：一条被诱导的命令就能把文件内容发出去。现在 Min 的 Bash 没有网络约束。

## 二、做法

1. **宿主侧 HTTP(S) 代理**：proot 里的网络请求经一个宿主进程里的代理转发（CONNECT 方式，只看域名，不解密内容）。代理按域名决定放行、拒绝或询问。这是 04 设计第 118 行「宿主侧网络代理按域名放行」的具体化。
2. **三种结论**：
   - 允许：名单里有（精确域名、`*.` 通配或 IP 字面量，可带 `:端口` 后缀只放行该端口，不带端口匹配所有端口——与 CC 的 `allowedDomains` 一致，cc-settings-reference.md `sandbox.network.allowedDomains` 一节）。各层设置的名单合并（项目层可以往用户名单里加，照原文 :2509）。
   - 拒绝：名单里的 `deniedDomains`，**优先于**通配允许（CC 原文同）。
   - 询问：都没命中。界面弹出批准卡：域名、请求的命令摘要、三个选项（允许一次 / 总是允许 / 拒绝）。
3. **记录**：「总是允许」写进设置（用户层，或当前工作区的本地层，与权限规则同一套存放），可在设置里逐条撤销。每次决定落日志（新事件 `network_decision`：域名、结论、来源 = 询问 / 名单）。
4. **托管锁**：`allowManagedDomainsOnly`（照 CC）开启时，只认托管层名单，询问直接拒绝。
5. **不解密**：只看 CONNECT 的主机名。HTTP 明文请求的路径与内容不检查（这一点写清楚：本设计防的是「往哪儿发」，不防「发什么」）。

## 三、与其他层的关系

- **与权限规则**：网络域名批准是**第二道**，前面仍是 Bash 的权限判定（命令本身是否允许）。命令被允许，不等于它能联网。
- **与 WebFetch**（2026-10-08 更正，照 CC 原文 cc-settings-reference.md :2639、:2657）：WebFetch 是进程内工具，**仍走它自己的权限规则**（`WebFetch(domain:…)`），不受沙箱名单约束；反方向，`WebFetch(domain:…)` 的**允许规则会并入沙箱名单**（沙箱名单 = `allowedDomains` + 这些允许规则里的域名）。
- **与审查模型（auto 模式）**：已核实 [CC 原文](https://code.claude.com/docs/en/sandboxing#hosts-outside-your-allowed-domains)：模型在 Bash 的 `allowed_domains` 中声明本命令所需域名，分类器同时审查命令与域名；带声明的命令即使已有允许规则也必须送审。通过后只对该命令有效，未声明的新连接拒绝，不在连接发生时调用分类器。明确 deny、strictAllowlist 与托管锁仍优先。
- **Android**：proot 里的网络经同一个代理。代理跑在 App 进程里，App 被冻结时代理停，命令的网络请求失败（这是可接受的，写进用户说明）。
- **桌面**：Windows 上的 Bash 经 Git Bash，同样设 `HTTP_PROXY` / `HTTPS_PROXY` 指向本地代理。不能强制（有的程序不认环境变量）——所以桌面的网络约束是「防误操作级」，写清楚。

## 四、与 seccomp 的分界

CC 在 Linux 上用 seccomp 硬禁网，Min 的 Android 上 proot 没有 seccomp 的同等能力。本设计只做「按域名放行」，**不声称是硬隔离**。硬隔离（禁止直连、只能走代理）留给 M5 的隔离层那一块，单独设计。

## 五、界面（随 B7 之后的界面单子）

- 批准卡：域名、来源命令摘要（截 80 字）、三个按钮；卡片写明「这个域名将被访问，请确认」。
- 设置页：「网络」一节：已允许的域名列表（可删）、拒绝列表、「只用托管名单」只读状态。
- 本期同时提供代理、名单读写、`network_decision` 事件、批准卡和设置页。

## 六、测试

- 精确域名、通配、`deniedDomains` 优先于通配；询问路径（用注入的回调模拟人的选择）；「总是允许」写入设置、撤销后再次询问；托管锁下询问即拒绝；日志即真相。
- 代理：CONNECT 到允许的域名通；到拒绝的域名 403；HTTP 明文请求同样按域名判。
- 变异：去掉 deny 优先、通配判断错误、托管锁不生效、询问结果不落日志。

## 七、不做的

- HTTPS 内容检查（不解密）。
- 公司代理自动发现与代理链：`httpProxyPort` / `socksProxyPort` 表示替换内置代理的用户自备回环代理，其过滤与可用性由用户负责，不是本代理的监听端口或上游转发端口。
- seccomp 硬禁网（M5 隔离层那一块）。

## 八、2026-10-09 核对后的实现口径

- 默认 `sandbox.enabled=false`，启用后空名单按权限模式处理；托管 `enabled` 锁定设置页开关。Default / AcceptEdits / Plan 询问；DontAsk 拒绝；Bypass 放行；Auto 仅允许已随命令审查过的声明。Min 暂无独立的 Plan 可用 bypass 标记，Plan 保守询问。
- 精确域名、`*`、`*.example.com`（不含根域）、IPv4、方括号 IPv6 与可选端口；主机名忽略大小写和末尾点。deny 始终先于 allow。未信任项目不能扩大 allow，deny 仍保留。
- managed-only 仅认托管 allow 和代理端口，各层 deny 继续合并。strictAllowlist 采用用户 / 托管设置；项目不能解除。WebFetch 的有效允许 / 拒绝域名分别并入沙箱名单，WebFetch 本身仍独立审批。
- 每命令随机凭据、回环监听、连接数限制、65 秒代理等待 / 60 秒内核批准等待；拒绝或超时无上游连接。HTTPS CONNECT 只转发字节。HTTP 检查 Host 与请求目标一致，单请求后关闭，避免拼接请求绕过判定。
- 决策先同步落日志再连接；重载与重启回放决策，孤立批准按拒绝收尾。总是允许写用户层精确 host:port；撤销来源条目后下次连接重新读取设置。
- 事件只记主机、端口、调用与结论，不记凭据、URL 路径或查询串。程序主动输出代理环境仍可能写入普通 Bash 输出，属于软隔离边界。
