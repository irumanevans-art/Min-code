# 内置工具规范（M1 · agent:tools）

M1 的六个工具：Read、Write、Edit、Glob、Grep、Bash。名字、入参名与 Claude Code 一致（模型对这套写法最熟，
用户从 CC 切过来提示词也不用改）；行为按 Min 的端口重做。接口见 `agent/spi/.../Tool.kt`、`Workspace.kt`。

## 1. 共同规则

- 包 `dev.min.agent.tools`，一个工具一个文件（`ReadTool.kt` …），每个工具是 `Tool<Input>`，`Input` 是该工具自己的 data class。
- 只通过 `ToolContext` 的端口碰外界（`fs` / `search` / `exec` / `artifacts`），不直接用 `java.io`、`java.nio.file`、`ProcessBuilder`。
  这样每个工具都能用假端口单测，Android 与桌面宿主各自实现端口。
- **路径**：入参里的路径必须是绝对路径（以 `/` 开头）；相对路径在 `parse` 里拒绝，错误信息告诉模型「请用绝对路径，当前目录是 ctx.cwd」。
  （`parse` 拿不到 ctx，所以只校验「是否绝对」；需要 cwd 的提示放在 description 里。）
- **parse 的错误信息写给模型看**：说清哪个字段错了、应该是什么样，让它下一次能改对。
- **description**：给模型看的说明，短而具体：做什么、什么时候用、关键限制。可以按 `HarnessProfile` 区分，M1 先一份通用的。
- **inputSchema**：JSON Schema（type object、properties、required、description），只用各家都认的子集（不用 `oneOf` / `$ref`）。
- **permissionAsk**：如实列出要碰的路径（带 `fs.scopeOf` 的分级与读 / 写）、命令、域名；`summary` 一句中文给人看。
- **结果**：成功 `ToolResult(content, isError = false)`；可预期的失败（文件不存在、没先读……）`isError = true` 且文字说明怎么办；
  预期外的异常直接抛，由内核兜成错误结果。读过或写过文件的，在 `touched` 里记下 `FileStamp`（路径、大小、mtime）。
- **traits** 如实标：只读 / 可并发 / 恢复策略（见各工具）。结果预算用默认值，除非下文另写。

## 2. Read

- 入参：`file_path`（必填）、`offset`（起始行，从 1 起，可选）、`limit`（行数，可选，默认 2000）。
- 输出：`cat -n` 风格，每行「行号（右对齐 6 位）+ 制表符 + 内容」；单行超过 2000 字符截断并标注；
  读到的不是文件末尾时，末尾说明「共 N 行，只显示了 a–b 行，用 offset/limit 读其余部分」。
- 空文件：返回一句「文件存在但是空的」（不是错误）。
- 图片（按扩展名 png / jpg / jpeg / gif / webp）：返回 `ImagePart`（base64）+ 一句说明；超过 5 MB 返回错误说明太大。
- 二进制（前 8 KB 里有 NUL 字节）：返回错误「这是二进制文件，不能按文本读」。
- 文本一次最多读入 8 MiB；超过时提示后面读不到，offset 不能越过这一字节预算，建议 Grep / Bash。
- 不存在 / 是目录：`isError`，说明情况（目录的话建议用 Glob 或 Bash ls）。
- `touched`：读到的文件的 stamp（即使只读了一部分）。
- traits：readOnly、concurrencySafe、`ResumePolicy.Replay`。

## 3. Write

- 入参：`file_path`、`content`。
- **先读后写**：文件已存在时，`ctx.lastSeen(path)` 必须存在，且与当前 `fs.stat` 的大小与 mtime 一致；否则 `isError`：
  没读过 →「修改已有文件前先用 Read 读一遍」；读后被改过 →「文件在你读过之后被改过，先重新 Read」。新文件不要求。
- 用 `fs.writeAtomic`；成功后 `touched` 记写入后的 stat。结果一句「已写入 <路径>（N 行）」。
- permissionAsk：该路径的 Write 访问。traits：默认（写、不可并发、Unknown）。

## 4. Edit

- 入参：`file_path`、`old_string`、`new_string`、`replace_all`（默认 false）。先读后写规则同 Write。
- 匹配链为精确 → 忽略行尾空白 → 缩进 → 标点归一化。每一级有匹配便停止，出现多处就拒绝，不能靠后级选一个；缩进匹配会调整新文本缩进。
- replace_all 只做逐字相同的替换；old_string 为空仅允许创建新文件或填空文件，已有文件仍要求先读。old_string == new_string 拒绝。
- 处理上限 10 MiB；前 8 KiB 检查 NUL；匹配按 LF，写回保留原 CRLF 和 UTF-8 BOM，writeAtomic 保留权限位。
- 结果为改动附近的带行号内容，从焦点前 4 行起最多 40 行，附放宽匹配说明及 touched；当前没有 unified diff。

## 5. Glob

- 入参：`pattern`（如 `**/*.kt`）、`path`（搜索根，可选，默认 ctx.cwd）。
- 结果按修改时间从新到旧排（需要逐个 `fs.stat`；宿主侧很快），最多 100 条，超出时注明「只列出前 100 条，请缩小范围」。
- 先由 Search 收集至多 1000 个候选再排序，超过 1000 时不保证得到全局最新的前 100 个文件。
- 没有结果：一句「没有匹配的文件」（不是错误）。
- traits：readOnly、concurrencySafe、Replay。permissionAsk：搜索根目录的 Read 访问。

## 6. Grep

- 入参（照 Claude Code）：`pattern`（正则）、`path`（可选，默认 cwd）、`glob`（文件过滤）、
  `output_mode`（`files_with_matches` 默认 / `content` / `count`）、`-i`、`-n`（content 模式下默认显示行号）、
  `-C`（上下文行数）、`multiline`、`head_limit`（默认 250）。
- 用 `search.grep`；`files_with_matches` 按文件去重后列路径；`count` 每个文件一行「路径:命中数」；
  `content` 为「路径:行号:内容」（上下文行用 `-` 代替 `:`）。超过 `head_limit` 截断并注明。
- 正则非法：`parse` 阶段用 `Regex(pattern)` 预检，拒绝并给出错误原文（ripgrep 语法与 Java 正则大体一致，差异放进已知限制）。
- `GrepQuery.maxHits` 只数实际命中（`isContext=false`），上下文不占配额；宿主逐文件按剩余配额扫描。
  `head_limit` 单独裁显示记录（含上下文，一条多行匹配仍算一条记录，组间 `--` 不计入）。
  若前置上下文超过显示上限，工具继续确认第一条实际命中，但最多保存 `head_limit + 1` 条显示记录，避免误报「没有匹配」。
  files/count 聚合上限为 20000 条实际命中，超过时提示结果可能不全。
- traits：readOnly、concurrencySafe、Replay。

## 7. Bash

- 入参：`command`（必填）、`timeout`（毫秒，可选，默认 120000，上限 600000）、`description`（给人看的一句话，可选）、
  `run_in_background`（可选）。
- 执行：`exec.run(ShellCommand(command, ctx.cwd), ExecOptions(timeoutMs, foregroundBudgetMs, maxOutputChars))`；
  `run_in_background = true` 时 `foregroundBudgetMs = 0`（立刻转后台），否则 `foregroundBudgetMs = 10_000`（跑 10 秒还没完就转后台返回句柄，Codex 的做法）。
- 结果：`Exited` → 输出 + 末尾「退出码 N」；退出码非 0 时 `isError = true`（输出照样给全）。`TimedOut` → isError，说明超时与已有输出。
  `Backgrounded` → 说明「已转入后台（id、日志路径），用 Read 查看日志」，并把句柄写进结果文字。
- M1 限制（写进 description）：每条命令都从会话目录开始执行，`cd` 与 `export` 不跨调用保留（M2 做持久 shell 状态）。
- permissionAsk：`commands = [CommandAccess(raw = command)]`，summary 用 `description` 或命令本身（截断到 80 字）。
- traits：默认（写、不可并发、Unknown）。

## 8. 测试要求

- 每个工具一个测试类，用内存里的假端口（假文件系统、假搜索、假进程）；不碰真实磁盘与进程。
- 覆盖：parse 的每种拒绝；正常路径；每种可预期失败；`touched` 的内容；Read 的分页与截断；Write 的先读后写三种情况；
  Glob 的排序与截断；Grep 三种输出模式与 head_limit；Bash 的三种结果与超时上限钳制；permissionAsk 的分级与读写标注。
- 期望输出手写。
