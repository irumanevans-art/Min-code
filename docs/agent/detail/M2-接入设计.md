## 2. M2-A 的设计决定

**包与位置**：`app/src/main/java/dev/min/code/core/engine/min/`（Min Agent 宿主）；调试入口在 `app/src/debug/`。只有这一个地方认识 Android 与内核两边。

**会话存储**：`filesDir/agent/sessions/`，App 私有目录、不在 rootfs 里（模型的 Bash 碰不到日志）。

**文件系统**：用 `:agent:host` 的 `RootfsFileSystem`，不新写映射：
- root = Claude Code 工作区的 `linux/` 目录（`WorkspaceRepository` / `WorkspaceManager.linuxDir`）；
- 挂载与 proot 启动参数**同一份来源**：`/workspace` → 工作区 `files/`；「让 agent 读写这台设备」开着时 `/sdcard` → 共享存储真实路径；
  不要另抄一份挂载表（`ProotShellRunner` / `WorkspaceShellContext.bindMounts` 是事实来源，HANDOFF 的 P1-3 就是因为四处各传各的）；
- `ScopeRules`：workspace = `/workspace`，device = `/sdcard`、`/storage`，与 `core/session/PermissionScope.kt` 一致；
- 现有 `guestToHostFile` 不认 bind mount 的问题，在 Min Agent 这条路上自然消失（旧引擎的那份不在本段改）。

**进程（`ProotExec`，实现 `Exec` 端口）**：
- 基于 `workspace` 模块现成的 `ProotShellRunner`（与 Claude Code 会话同一套 argv / env / 挂载），每条命令 `bash -lc`，cwd = 会话 guest cwd；
- 语义与桌面 `LocalExec` 一致：前台预算 10 秒，到时转后台并返回句柄；输出同时写日志，日志放 rootfs 的 `/root/.min/exec-logs/<id>.log`（模型能用 Read 看）；
- 超时、取消、kill 一律用 `ProcessTreeKill.reap`（HANDOFF P1-1：Android 上 `destroyForcibly` 没有强制语义，proot 扛得住 SIGTERM）；启动参数带 `--kill-on-exit`；
- **环境变量里不放任何凭证**（模型的 Bash 读得到 env）；环境快照、跨调用保留 cwd / export 留到 M3。

**供应商与凭证（`ProviderBridge`）**：
- Min 的 `ApiProfile`（DataStore 是唯一事实来源）→ `ProviderDescriptor`：地址照搬；方言 → `Wire`（Anthropic Messages / OpenAI Chat / OpenAI Responses）；
  `tokenEnvKey` 为 `ANTHROPIC_API_KEY` → `XApiKey`，为 `ANTHROPIC_AUTH_TOKEN` → `Bearer`；
- 模型：先在随包目录（`Catalog.bundled()`）里按「地址 + 模型 id」找；找不到就用保守的兜底描述（上下文窗口取 `ClaudeCodeModelCatalog.assumedContextWindow`），并在会话里留一条说明「未在目录中，能力按保守值处理」；
- 凭证：`Secrets` 端口直接从 `SettingsStore` 解密取 token，只进 HTTP 头；**Claude 订阅档不提供给 Min Agent**（订阅只能走官方 CLI，见 `ClaudeSubscription.kt`），桥在这一档上返回「不可用」并说明原因。

**投影（`MinAgentProjection`，纯函数）**：`SessionState` + 当前流式正文 → `List<ChatItem>` + 待审批描述 + `SessionStatus`。
- 历史里的用户消息 → `UserText`；助手消息的 thinking / text → `Thinking` / `AssistantText`；工具调用 → `ToolCall`（状态由调用阶段与结果决定，结果按 `withClippedResult` 截断）；
- 被中断 / 失败的回合 → `Note`（中断用普通色，失败用错误色）；收件箱里的输入 → `UserText(queued = true)`；
- 这是 Min Agent 填 `ChatItem` 的唯一一处，规则写在这里，不要散到界面里。

**调试入口（只在 debug 构建）**：一个 `BroadcastReceiver`，用 adb 触发：
`adb shell am broadcast -a dev.min.code.debug.AGENT_RUN -n <包名>/<类名> --es prompt "…" [--es approve yes|no] [--es session <id>]`。
它用当前激活的供应商开一个 Min Agent 会话（或续 `session`），跑完一句，把投影后的条目摘要、回合结局、用量逐行写到 logcat（标签 `MinAgentDebug`）。
用途：在接界面之前，就能在模拟器 / 真机上验证 proot 执行、路径映射、审批、进程被杀后的恢复。**release 构建里不存在这个类。**

## 4. M2-B 的形状（开工前再细化）

照 `min-internal.md` §8.2：`AgentSessionState`（去掉 CLI 专有字段）+ `AgentSession` 动作接口 + `EngineCapabilities`；
审批统一成 `PendingApproval { requestId, toolName, toolUseId, input, suggestions, kind }`；后台任务统一成 `BackgroundTask`；
会话列表抽 `SessionCatalog`（CLI JSONL / Codex rollout / 内核日志三个实现）。Claude Code 侧做成适配器，**行为等价**，先补 `ClaudeCodeSessionRegistry` 与 VM 的特征测试再动。
引擎按会话选：订阅 → 只能官方 CLI；API key / 中转 → 默认仍是 Claude Code，Min Agent 作为可选项，等 M2 验收后再改默认。
