# 记忆按需加载与自动记忆设计

> 状态：设计，2026-10-03。上位文档：`04-子系统设计.md` §4.6。
> 对标 Claude Code 的子目录 CLAUDE.md 按需加载、带 `paths:` 的规则、auto memory（`research/inventory/claude-code/03-extensions.md` §1）。实现是自己的。

## 0. 现状与目标

会话创建时的记忆快照（`MemoryLoaded`）已经有了：用户级、祖先目录的 `CLAUDE.md` / `.claude/CLAUDE.md` / `AGENTS.md` / `CLAUDE.local.md`、
没有 `paths:` 的规则、`@` 导入。缺三样：

1. **子目录记忆按需加载**：cwd 之下子目录里的 `CLAUDE.md` 等，模型读到那个子树里的文件时才加载（CC 同）。
2. **带 `paths:` 的规则**：模型读到匹配的文件时才注入（CC 同）。现在是跳过并记一条说明。
3. **auto memory**：`~/.claude/projects/<项目>/memory/MEMORY.md` 会话开始时进系统提示，模型用普通文件工具读写主题文件（CC 同格式）。

约束不变：请求能从日志逐字节重建；系统提示在会话内冻结（缓存）；分身前缀与父会话逐字相同。

## 1. 按需加载（1、2 两项）

### 1.1 触发

工具调用成功（`isError = false`）之后，看它的 `PermissionAsk.paths`（工具本来就报了自己碰的路径）：

- 读或写都算「碰到」（CC 说 reads；写之前模型基本都读过，算上更稳）；目录（Glob / Grep 的搜索根）不算，只算文件。
- 只看 cwd 之内的路径：cwd 之外的子目录记忆 CC 也不加载。

对每个碰到的文件 P：

- **子目录记忆**：从 cwd 的下一层到 P 所在目录（含），每层按启动时同样的顺序找 `CLAUDE.md`、`.claude/CLAUDE.md`、`AGENTS.md`、
  `.claude/rules/` 下没有 `paths:` 的规则、`CLAUDE.local.md`；其中的 `@` 导入照启动时的规则展开。
- **路径规则**：会话里所有带 `paths:` 的规则（启动时发现的：用户级、cwd 及祖先的 `.claude/rules/`；加上刚加载的子目录 `.claude/rules/` 里的），
  `paths` 的 glob 相对**规则所属项目根**（`.claude` 的上一级目录）匹配 P；命中就加载。

### 1.2 去重

同一路径一个会话只注入一次：状态里维护「已在上下文里的记忆路径」= 快照里的 + 按需加载过的。
**「视同已在上下文」的路径（`covered`）**：按需加载时有两种文件不会被注入、但内容已经在上下文里——与同批另一个文件内容相同而被跳过的
（同目录 `CLAUDE.md` 与 `AGENTS.md` 内容一样），以及模型这批直接 Read 过的记忆文件本身（内容在工具结果里，再注入是重复；它的 `@` 导入照常加载）。
它们记进 `MemoryAttached.covered`，折叠并进 `memoryPathsInContext`，不然下一批会把它们当没注入过的新文件再注入一遍。
`covered` 跟着挂靠的助手消息（`SessionState.memoryCovered`）：压缩摘要掉那条消息时与附件一起移出，分身继承时随附件原样复制。
**压缩例外**：按需加载的内容挂在消息上；那条消息被摘要掉（`ContextCompacted.through` 覆盖了它）之后，内容就不在模型视图里了——
压缩后把这些路径从集合里移出，之后再碰到就重新加载（CC 文档：压缩后重新读）。

### 1.3 落日志与进模型

新事件 `memory_attached`（放在 `spi/MemoryEvents.kt`）：

```
MemoryAttached(assistantMessageId, files: List<LoadedMemoryFile>, notes: List<String> = [])
```

- 挂在**发起这批工具调用的助手消息**上，渲染在这批工具结果之后（与 hook 的 `ToolResults` 上下文同一个位置，先 hook 后记忆的顺序固定）。
- `LoadedMemoryFile.content` 是进模型的原样文本（规则去掉 frontmatter、超长截断带说明），与快照同一套加工；`source` 新增 `nested`（子目录记忆）与 `path_rule`（路径规则）两个取值。
- 渲染：每个文件一段 `<system-reminder>`，头一行说明来源，例如 `Contents of src/api/CLAUDE.md (project instructions for this directory):`。
  措辞自己写，英文（与系统提示里的记忆段同一种语言）。
- 写入时机：工具结果（ToolOutcome）提交之后、下一次请求之前；同一批的多个调用合成一条事件。用 `Durability.Sync`。
- **坏路径只报一次**：读不了、不是文本、导入越界这类问题，`MemoryDiscovery` 在会话内存里记下路径（负缓存），之后同一路径不再读、不再说；
  只有说明（`notes`）或只有 `covered`、没有文件的事件用 `Durability.Batched`（不影响请求内容，不必每批都 fsync），带文件的仍是 `Sync`。
  重开会话后缓存丢了，多说一次而已。
- 上限：单文件沿用 `MemoryLimits.fileChars`；一条事件合计不超过 `MemoryLimits.totalChars` 的一半，超出的文件只给路径与「太长未加载，需要时用 Read 读」的一行。

### 1.4 子 agent 与分身

- 新开的子 agent：自己的会话，自己按需加载（它的快照里本来就有启动时的记忆）。
- **分身**：继承范围内的 `MemoryAttached` 原样复制（与 hook 上下文同理，见 `forkInheritance`），否则前缀对不上；
  发起委派的那条助手消息上的除外。分身的「已加载」集合随之继承。

## 2. auto memory

### 2.1 位置

- 项目键：cwd 所在 git 仓库的**主工作树根**（`.git` 是文件时读其中的 `gitdir:`，沿 `commondir` 找到主仓库；跨 worktree 共享，CC 同）；
  不在 git 仓库里就用 cwd。键 = 该路径里每个不是 `[A-Za-z0-9]` 的字符换成 `-`（`/root/proj` → `-root-proj`；CC 的目录名就是这样来的）。
- 目录：`<memoryHome>/.claude/projects/<键>/memory/`；`autoMemoryDirectory` 设置可改（绝对路径或 `~/`），**只认用户级与托管设置**——
  项目设置能把模型的写入引到任意目录，按「敏感键不认项目」处理。

### 2.2 开关

- `autoMemoryEnabled`（默认 true，各层 settings 都认），环境变量 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` 强制关（经 `KernelDeps` 注入的环境读取，不直接读进程环境）。
- 关掉时：不加载 MEMORY.md、系统提示里没有 auto memory 段。

### 2.3 进系统提示

- 会话创建时读 `MEMORY.md`：前 200 行或前 25 KB，先到为准；进 `MemoryLoaded` 快照，`source = auto`，会话内冻结（与其他记忆同）。
- 系统提示的记忆段之后加一段 auto memory 说明（自己写的英文，要点）：目录在哪；`MEMORY.md` 是索引、一行一条指向主题文件；
  四类笔记（user / feedback / project / reference）各记什么；什么不记（能从代码或 git 推出来的、已在 CLAUDE.md 里的、只对本次对话有用的）；
  先查有没有同主题的文件再写，更新而不是重复；索引超过 200 行时只加载了前 200 行，要合并整理。
  段里显示用量：`MEMORY.md: 37/200 lines`——模型据此知道该不该整理。
- 主题文件不预加载，模型用 Read 按需读。

### 2.4 写入与治理

- 模型用 Write / Edit 写这个目录。安全底线已豁免它（`CommandSafety.isProtectedPath` 的 `AGENT_NOTES`）。豁免只给干净的路径：记忆目录 / 计划目录之前或之后剩下的那段里还含 `/.git/`、`/.claude/` 片段，或文件名在受保护名单里（`.bashrc`、`.mcp.json`……）的不豁免，目录本身也不豁免。
- **权限**：
  - Default 模式：照常问人。审批卡就是「要记住这条吗」的勾选（04 §4.6 的「暂存勾选」先用审批卡实现），
    「总是允许」建议的规则是 `Edit(<目录>/**)`（Write 同），用户点一次就变成 CC 的行为。
  - acceptEdits：与工作区同等放行（这个目录是 agent 自己的笔记，CC 用户在这个模式下不会想被问）。
  - plan：照计划模式的规则（只读）。
  - bypass / dontAsk：照常。
- 冻结：会话内系统提示里的 MEMORY.md 不随写入变化（缓存）；下一个会话才看到新索引。说明段里写明这一点，免得模型以为写完就生效。

## 3. 事件与格式

- 新事件 `memory_attached`；`MemorySource` 新增 `nested`、`path_rule`、`auto`。登记到 `agent/store/FORMAT.md`。
- `SessionState` 新增：`memoryAttachments: Map<MessageId, List<LoadedMemoryFile>>`、`memoryPathsInContext: Set<GuestPath>`（折叠维护，压缩时按 1.2 移出）。

## 4. 测试要点（验收）

- 读 `src/api/x.ts` 后下一次请求里，那批工具结果之后出现 `src/api/CLAUDE.md` 的内容；再读同目录文件不重复；压缩掉之后再读会重新出现。
- `paths: ["src/**/*.ts"]` 的规则：读 `src/a.ts` 注入、读 `README.md` 不注入；子目录 `.claude/rules/` 里的路径规则相对子目录项目根匹配。
- cwd 之外的文件不触发；工具失败不触发；目录不触发。
- 分身：父会话有按需加载的内容时，分身首个请求的前缀与父会话逐字相同。
- auto memory：键的计算（含 worktree 指回主仓库）；200 行 / 25 KB 截断与用量行；关掉时没有段；`autoMemoryDirectory` 在项目设置里被忽略并记说明；
  acceptEdits 下写记忆目录不问、Default 下问且建议规则正确。
- 日志即真相：每个场景结束 `fold(日志) == 内存状态`。
- 变异：至少钉住去重、压缩后重新加载、路径规则相对根、分身复制、200 行截断、项目设置的目录被忽略。
