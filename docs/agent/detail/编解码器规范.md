# 编解码器规范（M1 详细设计 · agent:llm）

一种线协议一个 `ModelClient` 实现（`dev.min.agent.llm.<wire>` 包）。接口见 `agent/llm/src/main/kotlin/dev/min/agent/llm/`：
`ModelClient.kt`（请求、流式事件、异常）、`Provider.kt`（供应商与模型数据）、`Projection.kt`（共用的发送时投影规则）。
事实依据：`D:\kimi\workspace\research\inventory\providers\`（GLM 逐家抄录，带出处）。

## 1. 职责边界

编解码器**只做**两件事：规范请求 → 线格式；线格式的流 → `ModelStreamEvent`（或 `ModelException`）。
**不做**：重试、退避、记账、落盘、上下文压缩、执行工具——这些都是内核的事，编解码器做了就会和内核重复或打架。

构造：`XxxClient(provider: ProviderDescriptor, transport: HttpTransport, secrets: Secrets)`。只通过 `HttpTransport` 发请求，
只通过 `Secrets` 拿凭证；凭证只进请求头，不进日志、异常信息、`toString`。

## 2. 共同规则

**请求**
- 地址：`provider.baseUrl` 去掉末尾 `/` 再拼协议路径（Anthropic：`/v1/messages`；OpenAI Chat：`/chat/completions`）。
- 头：按 `provider.auth` 放凭证；`content-type: application/json`；流式加 `accept: text/event-stream`；再加 `provider.extraHeaders`；
  `user-agent: min-agent`。**不伪装成任何官方客户端。**
- 模型 id 用 `profile.wireModelId`；输出上限用 `request.maxOutputTokens ?: profile.maxOutputTokens`。
- 思考强度：组好请求体后 `body.deepMerge(profile.patchFor(request.effort))`（`Projection.kt`）。
- 助手消息的块先过 `partsToSend(parts, profile.ref, profile.reasoningEcho, inToolLoop)`；
  `inToolLoop` = 这条消息的下标 > `lastUserInputIndex(messages)`。
- DeepSeek Chat 最新规则：请求带 tools 时保留全部历史回合的 reasoning_content，目录用 Always；无 tools 时供应商忽略推理。Kimi K3 用 AlwaysIncludingEmpty，无推理的助手消息也发空串。WithinToolLoop 仍适用于只保留当前循环的其他模型。依据 2026-09-30 官方复核与 Flash 真网，见 catalog/SOURCES.md G5。
- 空文本块（`TextPart("")`）不发：多数端点拒收空内容块。
- `ImagePart` 的来源若是 `ImageSource.Artifact`，抛 `IllegalArgumentException`——附件由内核在组请求前内联成 base64，编解码器不读文件。
- 工具调用 id：日志里存的就是供应商给的 id。发给**有 id 格式限制**的协议时，把不合法字符确定性地替换成 `_`，
  同一个 id 在 tool_call 与 tool_result 两处必须替换成同一个值。

**流**
- 先发 `Started`，最后发 `Completed`；中间的增量只为界面观感。
- `Completed.message`：role = Assistant。Anthropic 按内容块顺序；Chat 把 thinking 聚成一个块放最前，普通 text / tool_call / opaque 保持相互次序。
- 工具调用参数：按块累积增量，结束时解析成 JSON 对象；空串 = `{}`；**解析失败** = `{"__invalid_json": "<原文>"}`
  （工具的 parse 会把它拒掉并告诉模型，比悄悄丢掉更好查）。
- `truncated` = 停止原因是输出上限（max_tokens / length）。此时内核不执行本条消息里的任何工具调用。
- **用量口径**（`Usage` 的 KDoc）：`inputTokens` 只算没命中缓存、也不是写缓存的输入；总输入 = input + cacheRead + cacheWrite。
- 停止原因映射到 `StopReason`，映射不了的放 `StopReason.Other(原文)`，不要丢。

**错误**（抛 `ModelException`，由内核决定重试）

| 情形 | kind | beforeFirstByte |
|---|---|---|
| 连接阶段 IOException / 首个 SSE 事件之前断开 | Network | true |
| 已收到事件后断流 | Network | false |
| HTTP 401 / 403；流中 `authentication_error` / `permission_error` | Auth | 看是否已收到事件 |
| HTTP 408 | Chat：Network；Anthropic：BadRequest，正文命中超长时 ContextOverflow | true |
| HTTP 429；流中 `rate_limit_error` | RateLimited（`retry-after` 头的秒数 → `retryAfterMs`） | 看是否已收到事件 |
| HTTP 529 / 流中 `overloaded_error` | Overloaded | 看是否已收到事件 |
| HTTP 5xx；流中 `api_error` | Server | 看是否已收到事件 |
| 普通 4xx 响应体匹配上下文超长特征 | ContextOverflow（鉴权 / 限流优先，不能把 5xx 判成超长） | true |
| HTTP 413 | Chat：ContextOverflow；Anthropic：仅正文命中特征才 ContextOverflow，否则 BadRequest | true |
| 其余 4xx（含 409） | BadRequest | true |
| 200 但响应不是预期的流（中转返回了错误页） | Other，message 带响应体开头 | true |

这是当前实现表，408 / 413 的跨协议差异尚待统一，结论与后续动作见 08；不能用 Chat 的测试证明 Anthropic 也做了同样的分类。

真实宿主 `UrlConnectionTransport.stream` 检查 Content-Type（忽略大小写，允许 charset），仅接受 text/event-stream。
2xx 的 HTML、JSON、缺 Content-Type 都抛 HttpStatusException(status, headers, body)，两种客户端一致映射 Other、beforeFirstByte=true、不可重试。
正文最多读取 2000 字节并保留 500 字符；有真实 loopback HTTP → transport → codec 的两协议测试。
FakeHttpTransport.Reply.Body 的脚本错误不代表生产响应，不能作为该链路的成功验收。

上下文超长特征：编解码器内置本协议的标准写法，另加 `provider.quirks.overflowPatterns`（正则）。
异常 message 写给人看，带状态码与响应体开头（Chat 最多 500 字符；Anthropic 最多 500 字符后可加省略号），**不带请求头**。

## 3. Anthropic Messages（`dev.min.agent.llm.anthropic.AnthropicMessagesClient`）

这是主干协议：Anthropic 本家，以及 DeepSeek、GLM、Kimi、Qwen、MiniMax、MiMo 的 `/anthropic` 兼容端点都走它。

- 头：`anthropic-version: quirks.anthropic.anthropicVersion`；`betaHeaders` 非空时 `anthropic-beta: 逗号分隔`。
- 体：`model`、`max_tokens`、`stream: true`、`system`（文本块数组）、`tools`（`name`/`description`/`input_schema`）、
  `tool_choice`（Auto→`{"type":"auto"}`，Required→`{"type":"any"}`，None→`{"type":"none"}`，Named→`{"type":"tool","name":…}`；无工具时不发）、`messages`。
- 消息：相邻同角色的消息合并成一条（兼容端点对交替更严格）。
  user：`text` / `image`（`source: {type: base64, media_type, data}`）/ `tool_result`（`tool_use_id`、`content` 为块数组、`is_error` 为真时才写）。
  assistant：`thinking`（`thinking` + `signature`）/ `redacted_thinking`（`data`）/ `text` / `tool_use`（`id`、`name`、`input`）。
- 工具调用 id 只许 `[A-Za-z0-9_-]`，按 §2 替换。
- 缓存（`quirks.anthropic.cacheControl` 为真时）：`cache_control: {"type":"ephemeral"}`（`cache.longTtl` 时加 `"ttl":"1h"`）打在三处：
  最后一个工具定义、最后一个 system 块、最后一条 user 消息的最后一个内容块。为假时请求里不出现任何 `cache_control`。
- `quirks.anthropic.thinkingSignature` 为假时，回传的 thinking 块不带 `signature` 字段。
- `redactedThinking` 为假时，redacted_thinking 整块不发。公共投影先丢弃来源不是当前 ModelRef 的 thinking / redacted / opaque，不转换为正文。
- 思考预算：若合并补丁后 `thinking.budget_tokens` ≥ `max_tokens`，把 `max_tokens` 提到 `budget_tokens + 1024`，
  但不超过 `profile.maxOutputTokens`；仍不满足就抛 `IllegalArgumentException`（模型数据写错了，要大声报出来）。
- 流：`message_start`（id、input / cache_creation / cache_read 用量）→ `content_block_start/delta/stop`
  （`text_delta`、`thinking_delta`、`signature_delta`、`input_json_delta`）→ `message_delta`（`stop_reason`、累计 `output_tokens`）→ `message_stop`；
  `ping` 不产生界面增量但计入收到过事件；`event: error` 映射 overloaded_error → Overloaded、api_error → Server、rate_limit_error → RateLimited、authentication_error / permission_error → Auth，其余先匹配超长再 BadRequest。
- `ToolCallStarted.index` 是本条消息里第几个工具调用（从 0 起），不是内容块下标。
- 停止原因：end_turn → EndTurn，tool_use → ToolUse，max_tokens → MaxTokens，stop_sequence → StopSequence，refusal → Refusal，其余 → Other。
  `model_context_window_exceeded` 也算截断（truncated = true），StopReason 仍是 `Other(原文)`。
- 合并相邻 user 消息后，`tool_result` 块必须排在其余内容之前（Anthropic 硬性要求；稳定排序，不动其余顺序）。
- 投影后一个块都不剩的消息整条不发。
- 已知限制：开启 thinking 时 Anthropic 只接受 `tool_choice` 为 auto / none。编解码器不改写（改写会掩盖调用方的意图），
  由上下文装配层在开启思考时避免 Required / Named。
- 超长特征至少含：`prompt is too long`、`exceeds the context window`、`input length and `max_tokens` exceed context limit`（大小写不敏感）。

## 4. OpenAI Chat Completions（`dev.min.agent.llm.openai.OpenAIChatClient`）

兜底协议：没有 `/anthropic` 端点的中转、本地模型，以及各家的 OpenAI 兼容端点。现有 `app/.../core/relay/` 里的转换代码有映射经验可参考，
但有三个已知缺陷**不许复现**：丢 `reasoning_content`、流式输入用量恒 0、`tool_choice` 的 any 没映射成 `required`。

- 体：`model`、`messages`、`stream: true`、输出上限字段名取 `quirks.openAiChat.maxTokensField`；
  `streamUsage == IncludeUsageOption` 时加 `stream_options: {"include_usage": true}`；
  有工具时 `tools`（`{type: function, function: {name, description, parameters}}`）与 `tool_choice`
  （Auto→`"auto"`，Required→`"required"`，None→`"none"`，Named→`{"type":"function","function":{"name":…}}`）；
  `parallelToolCalls` 为真且有工具时加 `parallel_tool_calls: true`。
- `parallelToolCalls=false` 是省略字段，不是发 false。`promptCacheKey=true` 且 cache.key 非空时发 prompt_cache_key；longTtl 不映射到 Chat 缓存参数。
- system：多个 system 串用 `\n\n` 连成**一条**消息放最前（保持前缀稳定）；`developerRole` 为真用 `developer` 角色，否则 `system`。
- user：只有文本时 `content` 是字符串，含图片时是数组（`{type: text}` / `{type: image_url, image_url: {url: "data:<mime>;base64,<data>"}}`）。
- assistant：文本块连成 `content`；工具调用放 `tool_calls`（`id`、`type: function`、`function: {name, arguments: <JSON 字符串>}`）；
  没有正文只有工具调用时，`content` 按 `emptyContentWithToolCalls` 写 null / "" / 不写。
  推理：`reasoningField` 非空时，把本消息保留下来的 thinking 文本拼起来写进该字段；
  `reasoningEcho == AlwaysIncludingEmpty` 且没有 thinking 时写空串 `""`（Kimi 不带就 400）。
- 工具结果：每个 `ToolResultPart` 一条 `role: tool` 消息（`tool_call_id`、`content` 为文本拼接）；
  `toolResultName=true` 时从历史工具调用补 name；
  结果里的图片按 `toolResultImages`：Inline 放进 content 数组，SeparateUserMessage 在这些 tool 消息之后补一条 user 消息装图片，
  Unsupported 换成一句文字说明「此处有 N 张图片未发送」。
- 流：`data: {...}` 逐块，`data: [DONE]` 结束。`choices[0].delta`：`content` → TextDelta；推理字段（`reasoningField`）→ ThinkingDelta；
  `tool_calls[]` 按 `index` 累积（首次出现带 `id` 与 `function.name`）。推理文本在 `Completed` 里组成一个
  `ThinkingPart(text, origin = profile.ref)`，放在正文之前。
- 工具身份可晚到、分段到达；收尾仍缺 id / name 时抛 Other，不编造工具。只读取 choices[0]。
  finish_reason 后继续读末块 usage，只在 [DONE] 交付 Completed 并停止上游；DONE 前 EOF / 断流为 Network。
  encryptedReasoningField 配置时，同模型的对应字符串累积到 OpaquePart 并回传；分段语义尚待豆包真网验证。
- 用量：`prompt_tokens`、`completion_tokens`、`prompt_tokens_details.cached_tokens`；DeepSeek 另有
  `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`，两套都认；还识别 prompt_tokens_details.cache_write_tokens。
  按 §2 口径：inputTokens = prompt − cacheRead − cacheWrite，缺字段有保守兜底。
- 停止原因：stop → EndTurn，tool_calls / function_call → ToolUse，length → MaxTokens，content_filter → Refusal，其余 → Other。
- model_context_window_exceeded 也置 truncated=true；deprecated delta.function_call 不解析，当前请求发送现代 tools。
- 超长特征至少含：`context_length_exceeded`、`maximum context length`，以及 inventory 里各家（DeepSeek / Kimi / GLM / Qwen）写明的超长报错。

## 5. OpenAI Responses（`dev.min.agent.llm.openai.OpenAIResponsesClient`）

G5 因用户提供的端点仅支持 Responses，提前落地本次所需协议能力；不代表 M4 的原生工具或全供应商验收完成。来源见 openai/RESPONSES_NOTES.md。

- 地址：provider.baseUrl + `/responses`；标准 Bearer，仍支持描述符的 XApiKey 和附加头。
- 体：model、stream=true、store=false、include=[reasoning.encrypted_content]、max_output_tokens、input、prompt_cache_key。system 串用两个换行连接为首条 developer input，工具定义平铺 type/function/name/description/parameters，显式 strict=false 保留已有可选参数。
- tool_choice 为 auto / required / none；Named 为 `{type:function,name:…}`。模型补丁表非空时仍按 patchFor 深合并；表为空时显式 effort 映到 reasoning.effort（off→none，max 无合法通用映射则先报错）。不改写用户的工具选择。
- assistant 的 message / reasoning / function_call 完整 output item 按同模型 OpaquePart 保留，包含 id、phase、encrypted_content、原始 arguments。发送时优先原始 item，不再次发送对应 TextPart / ToolCallPart。其他模型的 opaque 由公共投影丢弃；旧日志没有原始 item 时从规范块构造 assistant / function_call。
- 工具结果为 function_call_output，call_id 原样关联。文本 output 是字符串；含图则用 input_text / input_image 数组，未内联的 Artifact 明确拒绝。普通 user 图片也用 input_image。
- 流：response.created → typed deltas → response.completed / response.incomplete / response.failed。text/refusal delta 给 UI；reasoning_summary_text delta 只作为瞬时 ThinkingDelta。工具的 output_index 映射为调用序号。终止 response.output 是完整落盘依据，不用 UI 增量拼接替代。
- EOF / 断开且没有终止事件为 Network；终止事件后立即停止读取上游。HTTP 分类沿用 Chat；failed/error 走流中错误分类，保留取消异常。未知原生 output 类型明确 Other，不静默忽略。
- max_output_tokens incomplete → MaxTokens / truncated=true，内核不执行截断调用；content_filter → Refusal；其余 incomplete → Other 失败。缺少 / 重复 call_id、缺 name 明确 Other；坏参数仍以 __invalid_json 交给工具拒绝。
- usage.input_tokens 含缓存；inputTokens=total−cached_tokens−cache_write_tokens，缓存字段来自 input_tokens_details；output_tokens 已含 reasoning_tokens，不重复加。实测中转含额外 attribution 字段，不参与计数。
- 本次恢复无需服务端 previous_response_id；完整历史可从事件日志重建。前缀指纹覆盖客户端 system/tools，不覆盖中转自行注入的 instructions。

## 6. Gemini generateContent（`dev.min.agent.llm.gemini.GeminiClient`）

本节只定义经典原生协议，不混用 Interactions 的字段。官方事实来源见实现目录 `gemini/NOTES.md`；§2 仍逐条适用。

- 地址：baseUrl 可为主机根或已含 `/v1beta`（也接受 `/v1`），根地址补 `/v1beta`；模型去掉一次 `models/` 前缀再拼
  `/models/{wireModelId}:streamGenerateContent?alt=sse`。非流端点是同位置的 `:generateContent`，当前 ModelClient 只提供流。
  模型 id 必须是单个安全路径段。XApiKey 在此协议用 `x-goog-api-key`，Bearer 保留 OAuth 的 Authorization；凭证不进 URL。
- 体：`contents` 是 role=`user` / `model` 的 parts 数组；多个非空 system 用两个换行连接为 `systemInstruction.parts[0].text`。
  无工具不发 tools / toolConfig；有工具发 `tools:[{functionDeclarations:[{name,description,parameters}]}]`，
  `toolConfig.functionCallingConfig.mode`：Auto→AUTO、Required→ANY、None→NONE、Named→ANY 加 `allowedFunctionNames:[name]`。
  不发未经文档确认的 parallel 开关。图片为 `inlineData:{mimeType,data}`；Artifact 必须由内核先内联。
- `generationConfig.maxOutputTokens` 取请求或 profile；温度、topP、topK、stopSequences 等通过 profile 补丁设置。
  思考也是补丁：`generationConfig.thinkingConfig` 的 thinkingBudget / thinkingLevel / includeThoughts；不猜模型档位或预算，
  没有补丁则使用官方默认。includeThoughts 只控制可见摘要，不控制签名保留。合并后 candidateCount 仅允许 1。
- **schema 投影**走 `parameters`（OpenAPI Schema 子集），不走 parametersJsonSchema：递归保留
  type/format/title/description/nullable/enum/items/properties/required/minItems/maxItems/minProperties/maxProperties/
  minLength/maxLength/pattern/example/anyOf/propertyOrdering/default/minimum/maximum。
  type 字符串改大写；含 null 的 type 数组拆为 nullable=true 加非 null 类型（多类型改 anyOf）；const 改单元素 enum；
  enum 只接受字符串，非字符串显式拒绝，不能偷偷改变工具参数类型。int64 的六个 min/max 长度或数量字段改十进制字符串。
  `$ref` 仅支持本 schema 的 `#/...` JSON Pointer，展开引用、保留兄弟字段，循环 / 外部引用明确拒绝。
  oneOf 改 anyOf（不保留排他约束）；additionalProperties、$schema、$id、$defs、definitions、examples、allOf、not、
  if/then/else、dependentRequired、dependentSchemas、patternProperties、unevaluatedProperties、prefixItems、contains、
  minContains/maxContains、uniqueItems、multipleOf、exclusiveMinimum/exclusiveMaximum、readOnly/writeOnly/deprecated 等其他关键字删除。
  删除的约束由本地工具 parse 校验，不宣称模型侧仍 enforce。按输入键顺序遍历，数组不排序；同输入同输出，缓存前缀稳定。
- **调用 id**：FunctionCall 的 id 是可选字段，存在则原样保留。缺失时用 `gemini_<请求体 SHA256 前16位>_<调用序号>`，
  不依赖文本分片数或到达时间；不同参数的同名并行调用依靠独立序号区分。完整 functionCall 是一个 part，args 是对象，
  不拼接 Interactions 的 partial_arguments。坏 args 保留为 __invalid_json。重复 id / 缺 name 明确 Other。
- **回传**：Completed 同时保存规范 text/thinking/tool_call 和一个带 `geminiParts` / `geminiCallIds` 的同模型 OpaquePart，
  后者保存原始 part 顺序及调用关联，不给缺 id 的原始 functionCall 注入 id。回传优先原始 parts，避免规范块重复发送；
  functionResponse 从 callId 查 name 和原始 wire id，有 id 则回传，没有则省略，并按原始调用序号排列同名并行结果。
  多条相邻 user 合并后再排结果；一组无 id 并行结果必须齐全，不能跨 model 回合错配。结果文本放 response.output，错误放 response.error；
  结果图片放 functionResponse.parts[].inlineData。没有历史调用 / 重复结果明确拒绝。
- **思考与签名**：thought=true 的文本产生 ThinkingDelta / ThinkingPart(origin=profile.ref)；普通文本产生 TextDelta。
  thoughtSignature 可以附在文本、函数或空 part；原始 part 整体存入 opaque，签名不解码、不挪位、不和别的 part 合并。
  同模型有签名的 part 必须原样回传（优先于 reasoningEcho 的摘要过滤）；无签名 thought 按 reasoningEcho 过滤。
  跨模型公共投影丢弃 opaque/thinking，正文与工具规范块继续发送，绝不借用另一个模型的签名。
- **流生命周期**：每个 data 为 GenerateContentResponse；首个有效帧先 Started(responseId)，只读 candidate index=0。
  finishReason 后继续收集 usage-only 末帧；Gemini 没有 [DONE]，只有正常 EOF 且已见 finishReason（或 promptFeedback.blockReason）才 Completed。
  没有停止标记的 EOF、任何 IOException（包括 finish 后断开）都按 Network；流中 error 对象按 code/status 分类，不能吞掉已收到部分输出后的错误。
  空 part / 空 data 不发增量；签名单独空 part 仍存原文。未知有效内容类型明确 Other，不静默丢弃。
- **用量**：usageMetadata 是累计快照，有字段才覆盖，缺字段保留；inputTokens=max(0,promptTokenCount−cachedContentTokenCount)，
  cacheReadTokens=cachedContentTokenCount，cacheWriteTokens=0，outputTokens=candidatesTokenCount+thoughtsTokenCount。
  totalTokenCount 不重复计数；toolUsePromptTokenCount / 各模态明细不另加，当前没有服务端工具。
- **停止**：STOP→有函数调用时 ToolUse，否则 EndTurn（不能区分自然结束与 stopSequences）；MAX_TOKENS→MaxTokens/truncated。
  SAFETY、RECITATION、BLOCKLIST、PROHIBITED_CONTENT、SPII、IMAGE_SAFETY、IMAGE_PROHIBITED_CONTENT、IMAGE_RECITATION、
  ESCALATION、PUP_LIMITED_DISABLED→Refusal；MALFORMED_FUNCTION_CALL、UNEXPECTED_TOOL_CALL 等其余→Other(原文)。
  非 STOP 的失败停止不交付可执行 ToolCallPart，防止内核对 Other / Refusal 仍执行畸形调用；原文留在 opaque 便于诊断。
- **错误**：401/403 或 UNAUTHENTICATED/PERMISSION_DENIED→Auth；429/RESOURCE_EXHAUSTED→RateLimited（retry-after 秒）；
  408/DEADLINE_EXCEEDED→Network；503/UNAVAILABLE 与兼容 529→Overloaded；其他 5xx/INTERNAL→Server；404/NOT_FOUND、
  400/INVALID_ARGUMENT、FAILED_PRECONDITION→BadRequest。仅普通 4xx（流中 INVALID_ARGUMENT）且文本明确包含
  `input token count … exceeds … maximum`、`exceeds … maximum … token`、`maximum … context length`、`context window exceeded`、
  `prompt is too long` 或 provider 自定义正则时 ContextOverflow。500 即使文案提到长上下文仍 Server；通用 413 不凭状态猜上下文。
- **已知限制**：不做显式 cachedContents、googleSearch/codeExecution/urlContext 等内置工具、文件 API、实时 API、Interactions、
  服务端状态与多 candidate；cache.key / longTtl 不映射字段，隐式缓存依赖稳定前缀。目录模型资料不全时不猜必填窗口和输出上限。
  llm 层统一工厂覆盖四种 Wire；现有 CLI 工厂在允许修改范围之外，CLI 接入须后续任务处理。

## 7. 测试要求

- 编解码单元测试用 `FakeHttpTransport`（`agent/llm/src/test/.../FakeHttpTransport.kt`）与 `parseSse` 夹具，不连供应商网络。
  另以宿主 / CLI 的 loopback HttpServer 验证真实 HTTP 契约，尤其非 SSE 正文能到达两种客户端。
- **请求体快照**：关键场景的请求体与手写的期望 JSON 比较（两边都 `parseToJsonElement` 后比）。至少：纯文本；多 system + 工具 + 缓存断点；
  带 thinking 的多轮工具循环（含别家模型的 thinking 被丢弃）；effort 补丁合并；供应商怪癖开关各取非默认值一次。
- **流解析**：纯文本；thinking + 签名；多个工具调用（参数分多段、交错到达）；输出撞上限（truncated）；流中错误事件；首事件后断流。
- **错误分类**：§2 表里每一行至少一个用例，含 429 的 `retry-after`、各家超长报错原文（取自 inventory）。
- 期望值**手写**，不要先跑一遍再抄输出——手写才能发现实现与规范不一致。
