# WebFetch / WebSearch 设计

> 状态：设计，2026-10-02。对标 Claude Code 的同名工具（`code.claude.com/docs/en/tools-reference.md` 的「WebFetch tool behavior」「WebSearch tool behavior」两节，
> 2026-10-02 取，原文存于本机，未入库）。语义对齐，实现自己的。

## 1. WebFetch

**入参**（与 CC 相同）：`url`、`prompt`（要从页面里提取什么）。

**流程**：

1. 校验：`localhost` 与不含点的主机名直接拒绝，告诉模型用 Bash 的 `curl`（CC 同）；`http://` 自动升级为 `https://`。
2. 抓取：经宿主的 HTTP（不进 proot），`Accept` 优先 `text/markdown`、其次 HTML；`User-Agent` 以 `Min-Agent` 开头。
   跟随**同一主机**的跳转；跳到**别的主机**时不跟，返回「原地址 → 新地址」，让模型再调一次（CC 同：跨主机跳转要重新过权限）。
   截止 5 分钟（含跳转），可配置。
3. 转换：HTML 用 `dev.min.agent.tools.web.HtmlToMarkdown`（正文优先：main > article > body）；本来就是 Markdown / 纯文本的原样；其他类型（PDF、图片、二进制）说明类型与大小，不转。
4. **原文落附件**：转换后的完整 Markdown 存为会话附件 `web/<主机>-<短哈希>.md`。**这是 Min 比 CC 多的一步**：CC 只给模型提取结果（「lossy by design」，
   模型没问到的细节就丢了，只能重抓）；Min 同时给出附件路径，模型需要时用 Read 分段读原文，不必再联网。
5. 提取：用小模型按 `prompt` 从页面里提取（页面先截到固定上限，例如 100,000 字符）。小模型由宿主配置（`KernelDeps.fastModel`，没配就用会话当前模型）；
   提取请求是独立的一次请求，不进会话历史，用量计入本回合。提取失败（过载重试后仍失败）→ 返回错误结果，**不把 API 的错误文字当成页面内容**（CC 在 v2.1.212 修过同样的问题）。
6. 结果：`「<url> 的内容（按你的提问提取）：」+ 提取结果 + 「完整页面已存为 <附件路径>（N 字符），需要细节时用 Read 读取。」`

**缓存**：同一 URL 在宿主内存里缓存 15 分钟（可配置），缓存的是抓取 + 转换后的 Markdown；提取每次按新的 prompt 做。

**权限**：声明 `PermissionAsk.domains = [主机]`；工具不是只读（默认模式要问人，与 CC 的 Manual 模式一致——抓取能把对话里的东西带出去，
被网页里的提示注入诱导时尤其危险）。规则 `WebFetch(domain:example.com)` 照常生效，`suggestRule` 给的正是这条。
CC 内置了一批「免问的文档域名」；Min 第一期**不内置**（列表不公开，自己编一份容易放过不该放的），用户在设置里一键加常用文档域名的 allow 规则即可。

**端口**：`ToolContext` 增加有默认值的两个端口——`web: WebPort`（抓取，宿主实现，含缓存与截止时间）与 `extract(content, prompt): ToolResult`
（内核实现：用 fastModel 调一次模型）。没有宿主实现时工具返回「这个环境不能联网」。

## 2. WebSearch

CC 的 WebSearch 走 Anthropic 服务端的搜索工具，**只有 Anthropic 的模型能用**。Min 是多供应商的，所以做成**可插拔后端**：

- 后端接口（宿主实现）：`search(query, allowedDomains, blockedDomains, limit): List<SearchHit(title, url, snippet)>`。
- 第一期内置三种后端，用户在设置里选一个并填 key（key 走 Keystore，与模型 key 同等对待，永远不进 rootfs、日志、事件）：
  Brave Search API、Tavily、自建 SearXNG（只填地址）。都没配置时**工具不出现在工具表里**（工具表在进程内固定；配了之后新会话才有）。
- 入参与 CC 相同：`query`、`allowed_domains` / `blocked_domains`（二者不能同时给）。
- 结果：编号的「标题 — URL — 摘要」列表，不抓结果页（CC 同：要读页面再调 WebFetch）。
- **会话上限**：一次会话（含它委派的全部子 agent）最多 200 次（CC 同，可配置）；到上限返回一句「已用完本会话的搜索次数，请基于已有信息继续；需要更多时请用户放宽上限」，不是错误。
  计数在 SessionHub 里按根会话算。
- 权限：`WebSearch` 只接受不带限定符的规则（CC 同）。搜索只把查询词发给后端，默认模式下不问（只读）；用户可以写 `deny: ["WebSearch"]` 关掉。

## 3. 分期

| 期 | 内容 | 谁 |
|---|---|---|
| W0 | `HtmlToMarkdown` 纯函数 | Flash（进行中，`agent/web-html`） |
| W1 | spi 端口（WebPort、extract、SearchBackend）、WebFetch / WebSearch 两个工具与单测（假端口） | Sonnet / GPT |
| W2 | 宿主实现：桌面 CLI 与 App 的 WebPort（缓存、截止、跳转、Accept / UA）、三种搜索后端、fastModel 配置；内核的 extract 与搜索计数 | Sonnet / GPT |
| W3 | App 设置页：搜索后端与 key、常用文档域名一键放行（随 M2-B B7） | 随 B7 |
