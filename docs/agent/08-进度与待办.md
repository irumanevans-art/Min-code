## 2. 恢复门槛与验证口径

每个场景先执行正常基线，SessionCreated 持久后启用追加计数。k 表示允许 k 次追加成功，下一次追加之前永久抛 IOException；k=0 为首个用户输入追加前失败，k=N 为正常完成端点。
死亡锁存之后才取消协程，避免取消清理写入把「用户中断」混充「进程死亡」。使用真实 FileSessionStore，新的运行时打开同一会话。

| 场景 | 基线追加 N | k=0..N 子例 |
|---|---:|---:|
| 纯文本 | 6 | 7 |
| 两个并行只读工具 | 13 | 14 |
| 写工具审批允许 | 13 | 14 |
| 写工具审批拒绝 | 12 | 13 |
| 流式片段 | 7 | 8 |
| 请求失败重试 | 8 | 9 |
| 截断输出 | 9 | 10 |
| Steer 插话 | 13 | 14 |
| 回合中 Queue | 17 | 18 |
| **追加边界合计** | | **107** |
| UTF-8 尾记录每字节撕裂（含完整两端） | 2260 字节记录 | **2261** |
| **总计** | | **2368** |

107 中 98 是实际模拟死亡，9 是正常完成端点；另有 9 次正常基线未计入总数。共 2 个 JUnit 方法内枚举子例，不是 2368 个独立 JUnit 方法或随机 OS kill。
恢复断言：turn=null / 合法历史；成功 send 的 ID 与内容恰好存在一次；planRecovery 为空；重新 fold 等于内存；新输入可跑完；system / tools 与实际死亡前请求一致且 fingerprint 不变；再次 open 无新增记录；副作用不重放。
并行用双工具进入屏障证明；撕裂包含中文和 emoji，多字节中间切断，修复后字节一致、seq 连续且可追加重开。
还原后混沌测试连续执行 3 遍全绿，其中第 3 遍是十二模块完整 --rerun-tasks。未发现需修复的 kernel / store bug。

## 5. M2 第一批建议（本单未做）

1. Android 组合根先实现 WorkspaceFs / PathMapper：复用 RootfsFileSystem 的 guest-root 符号链接规则，绑定 `/sdcard` 到共享存储真实路径；明确 Workspace / Rootfs / Device 分级，覆盖 bind mount、绝对符号链接、`.l2s.`、越界和原子写权限位。

4. Keystore Secrets、生命周期与 FGS：模型 key 不进 rootfs / argv / 子进程环境；本地 CLI 的继承环境策略不能直接照搬 Android。重连快照、审批待办和前后台切换要真机验收。
