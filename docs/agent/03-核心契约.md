# 03 · 核心契约（M1 实现基线）

更新：2026-09-30。本文件描述当前代码；02、04 中的完整架构仍包含后续规划。实现状态与待办见 [08](08-进度与待办.md)。
跨模块值类型采用不可变 data class / sealed 类型；需要落盘的类型使用 `@Serializable`，纯运行时请求不强行序列化。

## 1. 规范值与持久事件

`:agent:protocol` 当前定义 ID、`ModelRef`、`PermissionMode`、`Effort`、`Usage`、`StopReason`、`Part`、`AgentJson`，尚无 MAP 命令或服务端消息。
`Part` 包含 TextPart、ImagePart、ThinkingPart、RedactedThinkingPart、ToolCallPart、ToolResultPart、OpaquePart；推理 / opaque 带来源模型，图片来源可为 inline 或 artifact。
`ModelMessage(role, parts)` 在 spi 中，是模型历史的规范形状。

`:agent:spi` 的事件没有公共 seq / 时间 / turnId 属性；存储包一层：

```kotlin
data class EventRecord(val seq: Long, val atMs: Long, val event: SessionEvent)
data class LogHeader(val formatVersion: Int, val sessionId: SessionId,
                     val createdAtMs: Long, val parent: SessionId? = null)
sealed interface SessionEvent
```

当前事件集（完整参数以 `spi/SessionEvent.kt` 为准）：

| 类别 | 已实现事件与关键字段 |
|---|---|
| 设置 | SessionCreated(cwd, model, mode, effort)、SettingsChanged(model?, mode?, effort?, cwd?) |
| 输入 | InputReceived(clientMsgId, parts, delivery)、InputPromoted(clientMsgId, messageId)、InputWithdrawn(clientMsgId)；delivery 为 Queue / Steer |
| 回合与请求 | TurnStarted(turnId, User / Resume)、ModelRequestStarted(turnId, requestId, attempt, model, prefixFingerprint)、ModelRequestFailed(kind, message, httpStatus?, willRetry) |
| 助手 | AssistantSegment(turnId, requestId, messageId, parts)、AssistantMessageCompleted(同上, usage, stop, truncated) |
| 工具 | ToolPlanned(turnId, callId, tool, input, resumePolicy)、ToolEffectPending(turnId, callId, handle?)、ToolOutcome(turnId, callId, result) |
| 审批 | ApprovalRequested(turnId, approvalId, callId, ask)、ApprovalResolved(approvalId, choice, decidedBy) |
| 收尾 | TurnEnded(turnId, outcome, usage, durationMs)，outcome 为 Completed / Failed(message) / Interrupted(by) |
| 展示 | Note(level, text)，不进入模型历史 |

ContextMasked、CompactionApplied、CheckpointTaken、子 agent / 自动化事件尚未实现。
事件格式 v1 的增量兼容规则、头格式与尾部修复见 `agent/store/FORMAT.md`；新增类型会让旧版本拒绝含该类型的日志，不能保证降级可读。

## 2. 当前运行时与恢复

`SessionRuntime.create/open` 接受依赖与协程 scope；`state: StateFlow<SessionState>` 是持久日志折叠状态，`live: SharedFlow<LiveUpdate>` 是可丢的瞬时增量。
公开操作包括 send、withdraw、interrupt、answerApproval、changeSettings、resume；具体签名见 `kernel/SessionRuntime.kt`。
所有状态改变先 append，再 fold；成功返回的 send 已持久化，同一个 clientMsgId 不重复接收。
输入先入收件箱，在安全点提升；Queue 等当前回合结束，Steer 在当前工具批结束后进入同一回合。
工具的执行门槛是完整回复、规划、审批、Sync 的 ToolEffectPending；截断回复的工具一律不执行。
只读且 concurrencySafe 的工具可并发，其余串行。

`open` 先折叠日志，再 Sync 追加 `planRecovery(state)` 的结果：缺失的 tool_result 都补齐，再用 ProcessDeath 结束旧回合。
助手回复已落盘、工具尚未规划的空档，也补 ToolPlanned + ToolOutcome。
恢复不会自动执行工具，包括标注 Replay 的只读工具；Replay / Reattach 目前只是恢复说明与后续优化意图。
EffectPending 的写操作明确报告「结果未知，先检查」，已完成副作用不重复执行。
半截 AssistantSegment 留给界面，不放入模型历史。再次打开无新增恢复事件；用户发新输入或 resume 才运行新回合。

## 4. 模型访问

`llm/Provider.kt`：ProviderDescriptor(id, baseUrl, wire, auth, extraHeaders, quirks)。
Wire 有 AnthropicMessages / OpenAIChat / OpenAIResponses / Gemini，客户端只实现前两种；AuthScheme 只有 XApiKey / Bearer。
ProviderQuirks 按协议分 AnthropicQuirks / OpenAiChatQuirks，另有 overflowPatterns；不是一张未实现的通用字段表。
ModelProfile 包含 ref、wireModelId、family、contextWindow、maxOutputTokens、supportsImages、editStyle、effortPatches、reasoningEcho。
effort 是请求体深合并补丁，缺少精确档位时取最接近档位，同距离取低档；null 不合并。
公共投影只回传相同 ModelRef 的 thinking / redacted / opaque，外模型这些块直接丢弃；同模型 opaque 目前不受 reasoningEcho 控制。

```kotlin
fun interface ModelClient {
    fun stream(request: ModelRequest): Flow<ModelStreamEvent>
}
```

ModelRequest 带 profile、system、messages、tools、toolChoice（默认 Auto）、effort、maxOutputTokens、cache。
事件为 Started(providerMessageId?)、TextDelta、ThinkingDelta、ToolCallStarted(index, id, name)、ToolInputDelta、Completed(message, usage, stop, truncated)。
没有 Failed / Stopped / ToolCallCompleted 事件；失败抛 ModelException(kind, httpStatus?, retryAfterMs?, beforeFirstByte)。
客户端只投影 / 编解码 / 分类；内核负责重试、记账、落盘、执行。当前内核按 retryable 与 maxAttempts 重发整个请求，不区分 beforeFirstByte；半截片段不进入模型历史，失败耗尽后合法收尾。压缩流水线尚未实现。
思考与 tool_choice 约束由请求装配层负责，当前装配始终 Auto；客户端不悄悄改写 Required / Named，未来装配入口需显式验证。
细节见 [编解码器规范](detail/编解码器规范.md)。

CLI 使用 Catalog.bundled()；现场覆盖端点、协议和 token 限额仍可用。凭证从环境读取，这是桌面组合根的宿主策略；Android 计划由 Keystore 实现 Secrets。
目录无默认环境变量字段时用 `<PROVIDER>_API_KEY`，可用 --api-key-env 覆盖；协议别名如 deepseek-openai 应显式指定 DEEPSEEK_API_KEY。
目录中地址有占位符时要求 --base-url，不能直接发请求。

## 5. 工具

Tool<I> 实际接口是 name、inputSchema: JsonObject、traits、description(profile): String、parse(raw): ToolInput<I>、permissionAsk(input, ctx)、run(input, ctx): Flow<ToolProgress>。
ToolInput 为 Valid / Invalid(messageForModel)；ToolProgress 为 Status / Output / Done(result)，最后必须有 Done。
ToolTraits 默认 readOnly=false、concurrencySafe=false、resumePolicy=Unknown、deferred=false、resultBudgetChars=30000。
ToolResult 带 content、isError、artifact?、fullChars?、touched: List<FileStamp>；stamp 为 path / size / modifiedMs。
ToolContext 只给 sessionId、callId、cwd、fs、search、exec、artifacts、lastSeen(path)；没有状态写权限或单独 progress 端口。
lastSeen 从结果中的 touched 折叠，重启后先读后写检查仍有效。
已实现六个工具，deferred / ToolSearch、按模型切换 ApplyPatch 尚未接线。

## 6. 宿主端口

| 端口 | 当前签名 / 契约 |
|---|---|
| WorkspaceFs | suspend stat(path)、read(path, offset=0, limit=Int.MAX_VALUE)、writeAtomic(path, bytes)、list(dir)；scopeOf(path)；宿主实现保留权限位 |
| Search | grep(GrepQuery): Flow<GrepHit>、glob(GlobQuery): Flow<GuestPath>；maxHits 只数 isContext=false 的实际命中，上下文不占配额 |
| Exec | suspend run(ShellCommand, ExecOptions): ExecResult、kill(ExecHandle)；没有独立 start / poll / stdin，run 可返回 Backgrounded |
| HttpTransport | suspend send(HttpRequest): HttpResponse、stream(HttpRequest): Flow<SseEvent>；非 2xx 或非 SSE 抛带正文预览的 HttpStatusException |
| Secrets | suspend apiKey(providerId): Secret?；Secret.toString 打码，仅 reveal 后入请求头 |
| ArtifactSink | suspend put(name, bytes): String，返回附件相对路径 |
| Clock / IdGenerator | nowMs(): Long / next(prefix): String |

ExecOptions 为 timeoutMs / foregroundBudgetMs? / maxOutputChars；ExecResult 为 Exited / TimedOut / Backgrounded(handle, outputSoFar)。
后台目前只能读日志；日志路径不等于实现了重启后的进程管理。Android 的进程组回收、持久追踪、环境快照见 08 的 M2 建议。
Checkpoints、Scheduler、CommandParser、Notifier、DeviceControl 等规划端口尚未实现。

## 7. 权限

PermissionAsk(tool, summary, paths, commands, domains) 以及 ApprovalChoice.Once / Always(rule) / Deny(note) 在 spi，审批由持久事件与运行时答复推进，没有挂起 Approvals 回调端口。
当前 PolicyEngine.evaluate(ask, readOnly, mode) 基于模式与路径 / 命令给 Allow / Deny / Ask；完整规则解析、hooks、tree-sitter 命令分析、auto 审查模型与隔离层仍是后续工作。
Always 当前只放行本次且记录选择，尚未写规则配置，不能把序列化字段当作已实现规则系统。
不实现的安全能力必须如实标注，不能把当前桌面壳声称为完整 Android 安全底线。

## 8. 存储

```kotlin
interface SessionLog {
    val header: LogHeader
    suspend fun append(events: List<SessionEvent>, durability: Durability): List<EventRecord>
    fun read(fromSeq: Long = 0): Flow<EventRecord>
}
interface SessionStore {
    suspend fun create(header: LogHeader): SessionLog
    suspend fun open(id: SessionId): SessionLog?
    suspend fun list(): List<LogHeader>
}
```

FileSessionStore 当前实现 `<root>/<sessionId>/events.jsonl`，头行 + 从 1 起连续的 EventRecord。两种 durability 都在返回前完成写入，Sync 另 fsync。
open 只裁最后换行后的半行；中部损坏或 seq 不连续拒绝打开且不改文件。快照、SQLite 索引、children 布局尚未实现。
CLI 组合根另提供 artifacts 附件宿主；不要把其附件目录归为 SessionStore 已实现的新接口。
M1 本次测试覆盖 107 个追加边界、2261 个 UTF-8 尾记录字节边界；具体口径见 08。
