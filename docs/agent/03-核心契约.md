# 03 · 核心契约（接口草图）

这里是**形状**，不是最终代码：字段会在各里程碑的详细设计里增删，但层次与依赖方向以此为准。
所有跨模块类型都是不可变 data class / sealed interface；跨 UI 边界的全部 `@Serializable`。

## 1. 持久事件（`:agent:spi` 定义，`:agent:store` 落盘）

```kotlin
/** 一条会话事件。日志 = 按 seq 排列的这些东西；内存状态 = fold(日志)。 */
@Serializable
sealed interface SessionEvent {
    val seq: Long          // 会话内单调递增，store 分配
    val at: Instant        // 来自 Clock 端口（测试里可控）
    val turnId: TurnId?    // 回合外的事件为 null
}

// 输入：先进收件箱，安全点再提升（永不丢输入、客户端 id 幂等）
InputReceived(clientMsgId, content: List<Part>, delivery = Queue | Steer)
InputPromoted(clientMsgId, messageId)

// 回合
TurnStarted(turnId, trigger = User | Resume | Goal | Loop | Cron | Workflow | Subagent)
ModelRequestStarted(requestId, model: ModelRef, prefixFingerprint, attempt)
AssistantSegment(messageId, parts)                    // 流式中攒批落盘，崩溃后用于展示半截
AssistantMessageCompleted(messageId, parts, usage, stop: StopReason, providerMeta)
TurnCompleted(turnId, usage, cost, durationMs, reason) / TurnFailed(error) / TurnInterrupted(by)

// 工具：持久化状态机 planned → effect_pending → outcome
ToolPlanned(callId, tool, input, resumePolicy)
ApprovalRequested(approvalId, callId, ask: PermissionAsk)   // 持久：进程重启后重新挂到 UI
ApprovalResolved(approvalId, decision, by = Rule(id) | Hook(id) | Classifier | User | Timeout)
ToolEffectPending(callId, handle: ExecHandle?)              // 副作用开始前最后一步（fsync）
ToolOutcome(callId, result: ToolResultRef, isError, artifacts)  // 大输出只存引用

// 上下文与会话元数据
ContextMasked(itemIds)                                  // 旧工具输出被遮蔽（原文仍在日志里）
CompactionApplied(summaryItemId, coversUntilSeq, sections)
ConfigChanged(mode | model | effort | cwd | outputStyle …) // 以追加消息表达，不改写前缀
CheckpointTaken(checkpointId, beforeTurnId)
SubagentSpawned(childSessionId, callId, spec) / SubagentFinished(childSessionId, reportRef)
Note(level, text)                                       // 给人看的，不进模型上下文
```

**格式纪律**：日志文件头写 `formatVersion`；新增事件类型或字段只加不改；旧版本永远可读；
读到比自己新的主版本直接拒绝并提示升级（学 OpenAI Agents SDK 的 RunState）。每次版本变更在
`agent/store/FORMAT.md` 追加一行说明。

## 2. 线协议（`:agent:protocol`，UI 与内核之间）

```kotlin
sealed interface Command { val commandId: CommandId }           // 幂等键
  SendInput(sessionId, clientMsgId, content, delivery)
  Interrupt(sessionId, expectedTurnId)
  AnswerApproval(approvalId, choice = Once | Always(ruleSuggestion) | Deny(note))
  AnswerQuestion(questionId, answers)
  SetMode / SetModel / SetEffort / SetCwd(sessionId, …, expectedTurnId?)
  Rewind(sessionId, toItemId, scope = Code | Conversation | Both)
  Fork(sessionId, atItemId) / Compact(sessionId, focus?) / StopTask(taskId) …

sealed interface ServerMessage
  EventBatch(sessionId, events: List<ProtocolEvent>, lastSeq)    // 持久流
  Delta(sessionId, itemId, kind, text)                           // 瞬时流
  Snapshot(sessionId, state: SessionSnapshot, atSeq)             // 重连用
  Request(requestId, kind = Approval | Question | PlanReview, …) // 服务端请求
  RequestResolved(requestId, by)                                 // 另一端已答，收起
  CommandRejected(commandId, reason)                             // 例：expectedTurnId 过期
```

`ProtocolEvent` 是 `SessionEvent` 面向 UI 的投影（去掉内部字段、大结果只给引用与预览）。
`SessionSnapshot` 是 ID 键控的覆盖式状态：items、待审批、任务、子 agent 树、后台任务、用量/上下文占比、当前模式与模型。

## 4. 模型访问（`:agent:llm`）

```kotlin
/** 规范消息：历史原样存这一种形状；发送时再投影到具体供应商。 */
data class Message(val role: Role, val parts: List<Part>)
sealed interface Part {
    Text(text) ; Image(ref, mime) ; Thinking(text, signature?, provider: ModelRef)
    RedactedThinking(data, provider) ; ToolCall(id, name, input: JsonObject)
    ToolResult(callId, parts, isError) ; Opaque(provider, json)   // Responses 的 reasoning item 之类
}

/** 一家供应商 = 端点 + 线协议 + 鉴权 + 怪癖。数据驱动，可被用户/中转覆盖。 */
data class ProviderDescriptor(
    val id: String, val baseUrl: String,
    val wire: Wire,                  // AnthropicMessages / OpenAIChat / OpenAIResponses / Gemini
    val auth: AuthScheme,            // XApiKey / Bearer / Custom(header)
    val quirks: Quirks,
)
data class Quirks(                  // 起点：pi-ai 的 compat 开关 + GLM 抄录的 10 家事实表
    val reasoningField: String?,     // "reasoning_content" …
    val reasoningEcho: EchoRule,     // Never / WithinToolLoop / Always / AlwaysIncludingEmpty(Kimi)
    val thinkingParam: ThinkingParamShape,   // 11 种形状之一
    val maxTokensField: String, val developerRole: Boolean,
    val toolChoice: Set<ToolChoiceValue>, val parallelToolCalls: Boolean,
    val toolResultNeedsName: Boolean, val emptyContentWithToolCalls: EmptyContent,
    val streamUsage: StreamUsageMode, val cache: CacheMode,   // AnthropicBreakpoints / AutoPrefix / PromptCacheKey / None
    val overflowSignatures: List<OverflowSignature>,          // 含「静默溢出」识别
)

interface ModelClient {
    /** 流式调用。编解码器负责：投影历史、组请求、解析 SSE、识别溢出、归一 stop reason。 */
    fun stream(req: ModelRequest): Flow<ModelStreamEvent>
}
sealed interface ModelStreamEvent {
    Started(requestId, model) ; TextDelta ; ThinkingDelta ; ToolCallStarted(id, name)
    ToolInputDelta ; ToolCallCompleted(call) ; Usage(u) ; Stopped(reason, truncated: Boolean)
    Failed(error: ModelError)       // RateLimited(retryAfter) / Overloaded / ContextOverflow / Auth / Network(beforeFirstByte) …
}
```
关键规则写在编解码器里而不是 kernel：`truncated=true` 时**不执行**本轮任何工具调用，只回「参数可能被截断，请重发」；
首字节前失败由编解码器重试，吐出部分后失败交 kernel 从上一个安全点重开。

## 5. 工具（`:agent:tools` 实现，`:agent:spi` 定义）

```kotlin
interface Tool<I : Any> {
    val name: String
    fun describe(profile: HarnessProfile): ToolDescription   // 按模型族给不同描述 / 形态
    val inputSchema: JsonSchema
    val traits: ToolTraits
    fun parse(raw: JsonObject): Either<InputError, I>        // 错误信息写给模型看，要能自我纠正
    fun permissionAsk(input: I, ctx: ToolContext): PermissionAsk   // 要碰哪些路径 / 命令 / 域名
    fun run(input: I, ctx: ToolContext): Flow<ToolProgress>  // 进度 …, 最后一条是 Result
}
data class ToolTraits(
    val readOnly: Boolean = false,          // 默认按「不安全」处理（学 CC：默认值取保守）
    val concurrencySafe: Boolean = false,
    val resumePolicy: ResumePolicy = Unknown,   // Replay / Reattach / Unknown
    val deferred: Boolean = false,          // 只露名字，经 ToolSearch 按需加载 schema
    val resultBudget: ResultBudget = default,   // 超了落文件，只给预览 + 路径
)
```
`ToolContext` 只暴露端口：`fs`、`exec`、`search`、`artifacts`、`session`（只读视图）、`progress`。
工具**不能**直接改会话状态，只能返回结果；这让它们可以在桌面 JVM 上用假端口单测。

## 7. 权限判定（`:agent:policy`）

```kotlin
data class PermissionAsk(val tool: String, val paths: List<PathAccess>, val commands: List<ParsedCommand>,
                         val domains: List<String>, val summary: String)
sealed interface Verdict { Allow(by) ; Deny(by, messageToModel) ; Ask(prompt, suggestions: List<RuleSuggestion>) }

interface PolicyEngine {
    /** 纯函数：同样的规则集 + 模式 + 请求 → 同样的判定。hooks 与审查模型在它之外由 kernel 编排。 */
    fun evaluate(ask: PermissionAsk, mode: Mode, rules: RuleSet, floor: SafetyFloor): Verdict
}
```
管线顺序（kernel 编排）：`PreToolUse hooks → PolicyEngine（deny→ask→allow，跨层 deny 赢）→ 模式 → 安全底线 →
（auto 模式）审查模型 → 人`。安全底线在任何模式下都不可绕过：对关键路径的删除、受保护路径写入、写 Device 分级、
解析失败的命令、下载后直接执行……一律到人。

## 8. 会话存储（`:agent:store`）

```kotlin
interface SessionLog {
    suspend fun append(events: List<SessionEvent>, durability: Durability)   // Sync（fsync）/ Batched
    fun read(fromSeq: Long = 0): Flow<SessionEvent>
    suspend fun snapshot(state: FoldedState, atSeq: Long)                     // 可重建，只为快
}
```
目录布局（每个会话一个目录，宿主私有存储里，**不在 rootfs 里**，免得被模型的 Bash 改掉）：
```
sessions/<sessionId>/
  events.jsonl        追加写，文件头带 formatVersion；fsync 在边界点
  snapshot.json       可删，删了从 events 重建
  artifacts/          大工具输出、压缩前原文、截图（模型经 Read 工具按需读，路径映射进 guest 只读视图）
  children/           子 agent 的会话目录（parentId 指回来）
index.sqlite          会话列表索引（标题、cwd、更新时间、花费、状态），可整体重建
```
