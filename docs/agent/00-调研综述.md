## 3. 做了取舍的地方

| 问题 | 选择 | 放弃的方案与理由 |
|---|---|---|
| 内核语言 | Kotlin / JVM | TS 要在 proot 里跑 Node（慢、重，装完 rootfs 才能用）；Rust / Go 增加第二语言与 JNI / IPC 边界，而 agent 循环是 IO 密集，性能收益用 ripgrep 二进制就能拿到 |
| 内核位置 | App 进程内，接口按可跨进程设计 | `:engine` 独立进程留到有数据证明需要时 |
| 扩展机制 | Kotlin 接口 + 构造注入；第三方一律进程外 | DeepSeek Harness 的动态插件框架：缺依赖静默不加载、组合层静默失效 |
| 线协议 | 自写 OkHttp + SSE | 官方 SDK 体积 28.5 / 63 MB，且 Min 未开 R8 |
| 协议基线 | 内部 MAP（Codex 三层）+ 外形对齐 ACP，M6 对外暴露 | 直接用 ACP 做内部模型：子 agent 树、后台任务、checkpoint 缺标准；AG-UI 同步审批要拆多次运行 |
| 框架 | 不依赖 Koog，只借抽象 | agents-core 连带服务端依赖；策略图对 coding agent 紧循环是过度抽象 |
| 压缩 vs handoff | 自动压缩为主，handoff 可选 | Amp 2026-05 推翻 handoff 改回 90% 自动压缩 |
| 默认权限模式 | default（CC 已默认 auto） | 手机上误操作代价高、proot 无沙箱；用户可改默认 |
| 检查点 | 编辑前内容 + JGit 影子仓库 | 每步 `git add --all`（proot 下太慢）；在 proot 里 fork git |

## 4. Min 自身的证据（为什么自研，见 01）

- CLI 适配层 77 条代表性补丁：形状猜测 18、版本漂移 13、功能缺口绕行 24、竞态 13、性能 5、平台 4（CLI 2.1.246–2.1.283）。
- 代码注释里的实测：改 effort 重启续会话 4–8 s；每会话 200–400 MB，最多同时 3 会话；rootfs 装好 533–550 MB；控制请求超时 8 s；
  SIGTERM 杀不死 proot。
- 新发现（未真机验证）：`guestToHostFile` 不认 bind mount，会把 `/sdcard` 映射到 rootfs 里的空挂载点；两份路径映射都按宿主解析符号链接。
- **M0 基线实测**（GLM，2026-09-29，模拟器 Android 15 x86_64、CLI 2.1.280，各 5 次取中位，
  数据与复现命令在 `researchaselineaseline-2026-09-29.md`）：

  | 项 | 宿主侧 | proot 内 | 倍数 |
  |---|---|---|---|
  | 遍历 `find /usr`（1969 文件） | 18 ms | 678 ms | **37.5×** |
  | 读 2379 个小文件 | 33 ms | 1663 ms | **50.3×** |
  | `grep -r` 同一目录 | 59 ms | 1533 ms | **26.2×** |
  | 起 100 次进程 | 404 ms | 338 ms | 0.84×（不慢） |

  - CLI 已是原生二进制：`claude --version` 34 ms；对本机 mock 的首 token 总时延中位 474 ms，其中 CLI 自身开销约 460 ms（含 proot 启动链）。
  - 内存：App 本体 PSS 188 MB，每个会话另有一个约 200–220 MB 的 claude 进程（3 会话合计约 605 MB）。
  - phantom process killer：两项配置均为 null，40 个孤儿进程 1 分钟内一个没被杀（**仅模拟器**，真机与 OEM 行为仍待测）。
  - proot 不带 `--kill-on-exit` 时会作为 ptracer 陪跑不退出；SIGKILL 掉 proot 后 tracee 全部存活——Exec 端口必须按进程组回收。
  - **结论**：proot 的开销集中在**文件系统调用**（26–50 倍），起进程本身并不慢。这直接支持「文件读写、搜索、快照在宿主侧做，
    proot 只跑 shell」；shell 环境快照的收益来自 login shell 初始化要读大量文件，而不是 fork 本身。
- 仍缺：真机（ARM）上的同组数字、OEM 杀后台时长。
