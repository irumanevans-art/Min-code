# 04 · 子系统设计（顶层）

每个子系统写三件事：**怎么做**、**借自哪里**（出处见 00-调研综述.md）、**比 Claude Code 好在哪**。
进入对应里程碑时，再在 `docs/agent/detail/` 下写该子系统的详细设计。

---

## 4.1 回合循环（kernel）

**怎么做**
- 显式状态机，而不是一个大 while：`Assembling → Requesting → Streaming → Dispatching → AwaitingApproval → Executing
  → (回到 Assembling | Finishing)`；每次「为什么继续 / 为什么停」都写成事件里的 `reason`（便于调试与评测归因）。
- 下一步做什么**只由已落盘的日志决定**（Goose 的 StateMachine 思路）：`nextStep(fold(log))` 是纯函数，
  桌面 JVM 上可以拿任意日志前缀做确定性回归。
- **流式中提前执行**：工具调用块一完整就进调度器；只读且并发安全的立刻跑（宿主侧文件工具没有 fork 成本，收益比 CC 大）。
- **调度**：连续的并发安全调用进有界池（默认 8），其余串行；结果按模型发出的顺序写回历史（完成顺序落盘）。
- **插话**：`Steer` 在当前工具批结束后、同一回合内送达；`Queue` 在回合结束后成为下一回合。用户插话不打断正在执行的工具。
- **停机条件**：模型无工具调用且无待办；`maxTurns`、`maxBudget`（钱）、循环检测命中、连续失败熔断。
- **重试**：首字节前的网络 / 429 / 529 由编解码器按 `Retry-After` 退避；吐出部分后断流，丢弃未落盘的半截，
  保留已完成的工具结果，从上一个安全点重开，最多 N 次（ZCode 的锚点重开）。
- **输出被截断**（stop=max_tokens 且有未闭合的工具调用）：不执行，回给模型「参数可能被截断，请缩小或分批重发」（pi）。

**比 CC 好在**：CC 不恢复中断的工具调用和后台任务；Min 的循环是日志的纯函数，任意点被杀都能续。
effort / 模型 / 模式热切，不重启任何进程（现在要重启续会话 4–8 s）。

## 4.2 供应商层（llm）

**怎么做**
- **四套线协议原生实现**：`AnthropicMessages`（主干：Anthropic 本家 + DeepSeek / GLM / Kimi / Qwen / MiniMax / MiMo 的
  `/anthropic` 兼容端点都走它）、`OpenAIChat`（兜底：没有 Anthropic 端点的中转与本地模型）、`OpenAIResponses`、`Gemini`。
  自己用 OkHttp + SSE + kotlinx.serialization 写，不引官方 SDK（Anthropic SDK 28.5 MB、OpenAI 63 MB，Min 没开 R8）。
  官方 SDK 只在桌面评测里做对拍。
- **怪癖表是数据**：`Quirks`（见 03 §4）从 pi-ai 的 compat 开关 + GLM 抄录的 10 家事实表起步，随 APK 带一份，
  用户和中转可覆盖。不支持的组合明确报错，不悄悄降级。
- **发送时投影**：历史用规范消息原样存；发送时按目标模型投影——同模型同签名组原样回传 thinking；换模型时 thinking 转普通文本
  或剔除签名块；按规则回传推理内容（DeepSeek 工具循环里必须回传否则 400、Kimi 连空串也要回、普通多轮 DeepSeek 忽略）；
  改写不合规的 tool call id；给悬空调用补结果；OpenAI 兼容端把工具结果里的图片拆成单独的 user 消息。
- **模型目录**：models.dev 快照随 APK（上下文 / 输出上限 / 是否推理 / 是否工具调用 / 价格含缓存价）→ 本地缓存 → 后台低频刷新
  → 叠加 Min 预设、用户配置、中转 `/models`。思考强度统一成 7 档，逐模型映射到各家参数，不支持的档就近取。
- **溢出识别表**：各家「上下文超长」的报错形状 + z.ai / MiMo 的静默溢出识别；命中后走「遮蔽旧输出 → 压缩 → 重试一次」。
- **用量与花费**：只信 usage（含 cache read / write），估算只用于发请求前的上下文表，并用每轮 usage 回填校准比例（中文按字符估会低估）。
- **Oracle / 顾问**：`ask_advisor` 工具（或自动在「计划 / 卡住 / 审查」时触发）把当前上下文交给用户配置的强模型，
  只回建议；主力跑便宜模型。等价并超越 CC 的 advisor（CC 只能在 Anthropic 服务端用）。
- **小模型位**：标题、摘要、WebFetch 提取、auto 审查、goal 判定可配独立的便宜模型。

**比 CC 好在**：CC 只会说 Anthropic 协议，国产模型靠中转且推理回传规则全靠运气；Min 每家按怪癖表正确处理。

## 4.3 工具与执行（tools + 宿主）

**工具集**（对标 CC 的 49 个，逐个见 05；这里只列形态决策）
- **文件**：`Read`（文本 / 图片 / PDF / notebook，带行号，大文件分段）、`Write`、`Edit`（精确替换 + 唯一性 + `replace_all`）、
  `apply_patch`（给 GPT 系的无行号补丁格式，先验证再审批再写）、`NotebookEdit`。按 `HarnessProfile` 二选一暴露 Edit 或 apply_patch。
  「必须先读、读后未被外部改过才能写」（Crush / CC）；匹配链：精确 → 空白归一 → Unicode 标点归一 → 缩进容错，
  匹配片段远大于原文就拒绝（OpenCode 护栏）；模糊命中时明确告诉模型改了哪里。
- **搜索**：`Glob`、`Grep` 在宿主侧用随 APK 带的 ripgrep（`librg.so`，W^X 与 `libproot_exec.so` 同一做法）跑在宿主路径上，
  结果映射回 guest 路径；纯 JVM 实现兜底。CC 在 Linux 上已去掉这两个工具改用 Bash——在 proot 里那是最慢的路。
- **Shell**：`Bash` 进 proot。login shell 只起一次并导出环境快照，之后每条命令 source 快照（Codex）；cwd / env 由内核持久化，
  常驻 shell 只是加速器，死了就用快照重建（mini-swe-agent 的「每步独立」语义）。命令默认前台等 10 s，未完成就转后台返回句柄；
  后台任务 = 现有托管进程表（pid + 日志文件），`Monitor` 按行把输出作为事件喂回模型。输出头尾各留一半，超预算落文件。
- **Web**：`WebFetch`（宿主侧抓取 → HTML 转 markdown → 小模型按问题提取，5 分钟超时）、`WebSearch`（后端可插拔：
  Anthropic 服务端工具 / Kimi `$web_search` / GLM web_search / Qwen enable_search / 用户配置的搜索 API）。
- **交互与编排**：`AskUserQuestion`、`EnterPlanMode` / `ExitPlanMode`、`TaskCreate/Get/List/Update`（+ `TodoWrite` 兼容）、
  `Agent`、`SendMessage`、`ListAgents`、`TaskStop`、`Skill`、`ToolSearch`、`CronCreate/List/Delete`、`ScheduleWakeup`、
  `EnterWorktree` / `ExitWorktree`、`Workflow`（M5）、`LSP`（M5）。
- **手机原生**：`Screenshot`、`DeviceTap/Type/Swipe`、`UiTree`、`LaunchApp`（现有 7 个设备工具转原生）、`Notify`（=CC 的 PushNotification）、
  `SendUserFile`（推到分享面板）、`OpenPreview`（预览槽，点了才开）、`Clipboard`、`OpenUrl`（Custom Tab，需确认）。
- **常驻少、其余按需**：默认常驻约 12–15 个；MCP 工具、低频工具只露名字，经 `ToolSearch` 加载 schema，加载后追加到工具表末尾
  （不重排，保缓存）。Cursor 这么做工具描述 token 降 60%，Copilot 砍到 13 个工具成功率反升 2–5 个百分点。

**路径映射（宿主实现的地基，先写测试）**：一个 `PathMapper` 取代现有两份不一致的实现——guest 路径 → 宿主路径，
认 bind mount（`/sdcard` → `/storage/emulated/0`），**按 guest 根解析符号链接**（`/lib → usr/lib` 不能按宿主解析），
识别 proot `--link2symlink` 的 `.l2s.` 文件，原子写保住权限位。任何映射到 rootfs 之外（且不在 bind mount 内）的解析结果一律拒绝。

## 4.4 权限与安全（policy + kernel 编排）

**怎么做**
- **规则语法兼容 CC**：`Tool` / `Tool(specifier)`；Bash 前缀 + `*`；Read/Edit 用 gitignore 式路径；`WebFetch(domain:)`；
  `mcp__server__tool`；`Agent(名)`；参数级规则只用于 deny/ask。判定 deny→ask→allow，跨层 deny 赢。
  层级：managed（Min 设置里的「锁定」）> 会话 > 本地 > 项目 > 用户；**敏感键（默认模式、auto 配置）不认项目文件**（防仓库自我放权）。
- **模式**：default / acceptEdits / plan / auto / dontAsk / bypass，与 CC 同名同义。默认模式在隔离层（§4.4.1）落地后定为
  「隔离内自动」：隔离范围内的命令不逐条问，越界才弹卡片；隔离层落地前默认 default。用户可改默认。
- **路径分级**：沿用 Min 的 Workspace / Rootfs / Device；写 Device（手机真实文件）在任何模式下都要人确认，朱色警示。
- **命令分析**：宿主侧只保留**一套**解析器（tree-sitter-bash）：拆成简单命令逐个对规则；重定向视为对目标路径的写；
  `bash -c` / `eval` / 解释器 `-c` 剥开再查；**解析失败 = 不信任 = 问人**。CC 新旧两套解析器并跑正是回车符绕过的来源，Min 不重蹈。
- **安全底线**（任何模式不可绕过）：关键路径删除（`/`、家目录、顶层目录）、受保护路径写入（`.git/hooks`、`.git/config`、`.claude`、
  `.mcp.json`、shell rc、`.gitconfig`）、下载后直接执行、Device 写入、未解析变量的 `rm -rf`。
- **auto 模式**：规则先行 → 只读与工作区内编辑直接放行 → 其余交审查模型（只看用户消息、非只读工具调用与 CLAUDE.md，
  **剥离工具结果与助手文本**，防注入）→ 被拒的原因作为工具结果给模型换路 → 连拒 3 次或累计 20 次转人工。
  进入 auto 时丢弃「任意代码执行」类宽规则（`Bash(*)`、解释器通配等），离开时恢复。审查模型可配便宜模型。
- **对话里的边界**：用户说「别 push」这类话，由内核抽成结构化约束存进会话（CC 每次从 transcript 重读，压缩后会丢）。
- **审批体验**：卡片与通知按钮三键——本次允许 / 总是允许（给出按最长前缀归类的建议，如 `git checkout *`）/ 拒绝（可附一句话给模型）。
  审批是持久事件，进程重启后仍在；两端先到者生效。
- **信任**：首次进入项目目录时确认信任；项目级 hooks / MCP / 规则 / 插件在信任之后才生效（CC 修过三起「信任前执行」漏洞）。
- **如实标注隔离程度**：见 §4.4.1。不宣称做不到的隔离。

### 4.4.1 自建隔离层（Codex / CC 式沙箱在 Android 上的等价物）

Codex 用 Landlock（限写）+ seccomp（禁网），Claude Code 用 bubblewrap（命名空间）+ 网络代理。2026-09-30 查资料 + 模拟器实测
（`research
eportsndroid-sandbox.md`、`android-sandbox-probes.md`，Android 15 / 内核 6.6）的结论：

| 手段 | Android 上 | 证据 |
|---|---|---|
| bubblewrap / user namespace | **不可用**：内核未开 `CONFIG_USER_NS`，`unshare(CLONE_NEWUSER)` = EINVAL；GKI 全分支都没开 | 实测 + gki_defconfig |
| Landlock | **不可用**：`landlock_create_ruleset` = ENOSYS，`CONFIG_SECURITY_LANDLOCK` 未编入；GKI 只有 android16-6.12 起才开，且应用 seccomp 未登记该系统调用 | 实测 + gki_defconfig |
| seccomp-bpf 叠加 | **可用**：应用可叠加过滤器；在 proot guest 里装上后 proot 照常工作（bash / node / claude / npm 全通，负载计时差异在噪声内），过滤器随 exec 继承到子孙进程；ERRNO 优先于 proot 的 TRACE | 实测 |
| io_uring | 系统已禁（EACCES），我们仍显式拒绝作纵深防御 | 实测 |
| proot 策略 | proot 自身没有只读绑定、路径白名单、网络隔离；**guest 里的 `mount --bind` 会被 proot 翻译成真的动态绑定**，`unshare` / `mount` 一律假成功 | 实测 |
| Android 应用沙箱 | 天然存在：对其他应用与系统是硬边界；对 Min 自己的私有数据没有边界 | 资料 |

**分层与强度**（界面上逐层如实显示，不笼统地说「沙箱」）：

| 层 | 做什么 | 强度 | 里程碑 |
|---|---|---|---|
| L0 应用沙箱 | 系统给的 | 硬（对外），对 Min 自身无 | 已有 |
| L2 seccomp 过滤器（guest 进程树） | ① 禁网模式：`socket(AF_INET/AF_INET6)` → EPERM；② 始终禁：ptrace、mount / umount / pivot_root、unshare / setns、bpf、perf_event_open、keyctl 系、userfaultfd、process_vm_*、io_uring、模块与 kexec；③ 装完后禁 `seccomp()` 与 `prctl(PR_SET_SECCOMP)`，堵住「guest 自己装 USER_NOTIF 压过 proot 的 TRACE」这条旁路；④ 非本机 ABI 一律拒 | **按值判定的部分是硬的**（禁网、禁危险调用）；看不到路径与 connect 目标 | M2 |
| L1 proot 策略（自维护的 proot） | ① proot 退出时 tracee 一起结束（PTRACE_O_EXITKILL；基线实测现在杀掉 proot 后 tracee 全部存活且脱离路径翻译）；② 可写路径白名单（工作区 + /tmp + 缓存目录），越界写返回 EACCES；③ 屏蔽非本进程树的 `/proc/<pid>`，保护 Min 主进程；④ 联网模式下 connect 只许连本机代理端口 | **防误操作级**：挡得住模型误操作和提示注入诱导的普通命令（静态二进制、Go、`python -c` 都要经 proot）；挡不住蓄意写的多线程竞态逃逸代码 | ① M2，②③④ M5 |
| L3 网络代理 | 宿主侧 HTTP(S) 代理按域名放行（CC sandbox-runtime 的做法），在界面上逐域名批准 | 防误操作级（依赖 L1 的 connect 限制） | M5 |
| L4 宿主判定 + 检查点 | 宿主侧文件工具在 Kotlin 里执行同一份路径策略（无竞态，硬）；每回合前 JGit 快照，覆盖 Bash 改动，可回滚 | 硬（宿主工具）/ 可恢复（Bash） | M2 / M3 |

**一处定义，两处执行**：可写路径白名单、网络模式由 policy 模块产出一份策略，宿主侧工具直接用，同时序列化给 proot / seccomp 启动器。不各写一份。

**默认配置**（对齐 Codex 的 workspace-write + 网络关）：网络关（L2，硬）+ 写限工作区（L1，防误操作）+ 每回合快照（L4）。
在此之内的命令自动执行；要联网、要写工作区外、要碰 Device 分级时弹卡片（可选「本会话内对该域名 / 该路径放行」）。
Cursor 实测「沙箱内免批、出界才问」让 agent 停下来的次数少 40%。

**界面文案**：逐项显示本机探测到的真实状态，例如「网络：已断开（内核强制）」「写入：限于工作区（防误操作级）」
「命令仍以 Min 的 Android 身份运行」。不写「沙箱」「安全隔离」这类笼统说法。现有 `IS_SANDBOX=1` 只是为了过 Claude Code 的
root 检查，界面不得把它当成「有沙箱」。

**研究项（不排期）**：seccomp USER_NOTIF + 监督者代为执行 connect / open 并注入 fd（Sandlock 的做法），是 Landlock 缺位时唯一竞态安全的
按路径 / 按目标放行方案；模拟器上已确认能拿到 listener fd，但实现复杂，等 L1 / L3 的防误操作级不够用时再评估。

## 4.5 上下文与缓存（context）

**怎么做**
- **稳定前缀**：`[系统身份 + 工具使用规范（按 HarnessProfile）] [工具表（固定排序）] [记忆文件（会话中冻结快照）]`
  ——会话内逐字不变；日期、cwd、git 状态、模式、模型变化等**世界状态**拆成带类型的段落，只在变化时在对话末尾追加一段 diff（Codex）。
  计划模式不改工具表，用追加消息说明限制（DeepSeek Harness）。
- **缓存断点**（Anthropic 语义）：最后一个工具定义、最后一段 system、最新一条用户消息；主会话默认 1 h TTL（手机上断续使用）。
  自动前缀缓存的供应商（DeepSeek / GLM / Kimi…）同样受益于前缀纪律。每次请求记录前缀指纹，UI 显示命中率与失效原因。
- **大输出落文件**：超过工具预算的输出写进会话 artifacts，只给模型预览 + 路径，模型用 Read / Grep 按需取（Cursor / Manus / CC）。
- **压缩流水线**（从便宜到贵，失败 3 次熔断）：① 遮蔽旧工具输出（保护最近约 40k token），攒够一批才改写一次，减少缓存失效；
  ② 结构化摘要：固定分区（目标、决定、改过的文件、待办、错误与教训），**「改过哪些文件」由内核自动记录**不靠模型回忆，
  增量合并旧摘要，摘要变长就放弃；③ 溢出时最多重试一次。原文永不删除，UI 仍可看全文，摘要里给模型指向原文的路径。
  OpenHands 实测「一上来就 LLM 摘要」打断缓存、总成本反而高，所以遮蔽优先。
- 细节（事件、阈值、攒批、摘要请求复用前缀、撞墙只重试一次、熔断、恢复）见 `detail/压缩设计.md`。
- **压缩后重挂**：CLAUDE.md、已调用的 skill 全文、计划、任务表、最近读过的关键文件摘要。
- **循环检测**（零 token 优先）：工具调用周期性重复、流式文本复读、同一错误连续出现；第一次追加提醒，第二次停下弹卡片。
  LLM 判定卡死只在长任务、且默认关。
- **handoff** 作为可选命令（带摘要开新会话），不是主路（Amp 已在 2026-05 改回自动压缩）。

## 4.6 记忆（context + ext）

- **读**：`CLAUDE.md`（managed → 用户 → 项目根 → 子目录按需）、`CLAUDE.local.md`、`AGENTS.md`、`.claude/rules/**`（带 `paths` 的
  读到匹配文件时才注入）、`@import`（最多 4 跳、代码块内不解析、指向工作区外要批准）。与 CC 语义一致，用户零迁移。
- **auto memory**：与 CC 同格式（`MEMORY.md` 索引 + 四类主题文件），但加治理：常驻部分硬上限并在提示里显示用量；
  会话中冻结快照（保缓存）；**后台写入先暂存**，以「学到了 N 条」卡片让用户逐条勾选才生效；前台（用户明确要求记住）直接写。
  理由：自动沉淀技能 / 记忆会把不安全行为跨会话固化（Hermes 的教训、arXiv 2608.12851）。
- **反思**：在压缩时或会话结束后触发，交给 WorkManager 限定「充电 + 不计流量」时跑。

## 4.7 扩展：Claude Code 生态兼容（ext）

- **配置发现**：用户级 `~/.claude/`（rootfs 的 `/root/.claude`）与项目级 `.claude/`：`settings.json`（permissions、hooks、env、model…）、
  `agents/*.md`、`commands/*.md`、`skills/*/SKILL.md`、`output-styles/`、`.mcp.json`、插件目录。同时读 `AGENTS.md` 与
  Agent Skills 标准位置。Min 自己的偏好不写进这些文件（DataStore 仍是 Min 配置的唯一事实来源）。
- **hooks**：33 个事件与 CC 同名同语义（stdin JSON、exit 0/2、stdout 决策字段）。执行方式重做：command hook 进 proot，
  同一事件的多个 hook **合批进一次 proot 调用**；另支持宿主内 hook（Kotlin，首方用）与 http hook；默认超时远低于 CC 的 10 分钟；
  `/goal` 实现为会话级 prompt 型 Stop hook（与 CC 一致）。也能执行用户现成的 Codex `hooks.json`（DeepSeek Harness 的做法）。
- **skills**：描述常驻（有预算），调用时全文作为一条消息留驻；`context: fork` 在子 agent 跑；`allowed-tools`、`paths`、
  `disable-model-invocation` 语义对齐；压缩后重挂。
- **plugins**：CC 插件目录格式（manifest、skills、agents、hooks、`.mcp.json`、output-styles、bin 进 PATH）与 marketplace 源（git / url / archive+sha256）。
  可执行部分一律进程外；安装时展示权限与来源，默认不启用第三方市场。
- **MCP**：官方 kotlin-sdk-client 外包一层；stdio server 进 proot，HTTP / WebSocket server 宿主直连；OAuth 走 Custom Tab；
  resources（`@` 引用）、prompts（变斜杠命令）、elicitation（弹提问卡）；工具经 ToolSearch 按需加载；结果超限落盘。
- **output styles**：与 CC 同格式与语义（替换角色与格式指令段）。

## 4.8 多 agent 与自动化（kernel）

- **子 agent = 带 parentId 的持久子会话**，委派时就落盘，父回合不在内存里干等（Roo / Kilo）；定义文件与 CC 同格式
  （tools / model / permissionMode / maxTurns / skills / mcpServers / hooks / memory / background / isolation / effort）。
  内置 Explore / Plan / general-purpose。默认后台；fork 模式继承完整前缀以命中缓存；嵌套与并发有上限（手机默认并发 2–3）。
  子 agent 的审批浮到主会话；UI 的子 agent 树直接来自事件，不再猜「agentId 三方同一性」。
  细节（事件、分身前缀逐字节等同、报告恰好交付一次、恢复表）见 `detail/子agent设计.md`。
- **SendMessage / ListAgents / 收件箱**：一等公民的邮箱，投递在对方的安全点发生（替代现在借 hook 回调旁路递话）。
- **并行写不加全局锁**（2026-10-01 修订，原为「写操作单线程」）：锁会把平等 agent 的吞吐退化到 1–3 个（Cognition / Cursor 的教训），
  同一文件的冲突已由每个会话的「先读后改、读后没被外部改过」检查抓到；真要并行改同一片代码，用 worktree 隔离。
- **worktrees**：`EnterWorktree` 建在 `.claude/worktrees/<name>`，git 操作在宿主侧用 JGit 做。
- **工作流（M5）**：CC 的 dynamic workflow 语义（`agent()` / `parallel()` / `pipeline()` / `phase()`），脚本在内嵌 QuickJS 里跑、
  无文件与 shell 访问、禁用时钟与随机数；每个节点的结果写日志，进程被杀后重跑时已完成节点直接回放（ZCode / CC 同法）。
- **定时 / 循环 / 目标**：`CronCreate`、`/loop`、`ScheduleWakeup`、`/goal` 语义对齐 CC，但触发交给 Android 调度
  （WorkManager / 精确闹钟 → 拉起 FGS → 内核续跑），**不假设进程常驻**；错过的触发按策略补或跳，并通知用户。
- **其他引擎当子 agent**：Claude Code CLI（订阅用户自己登录的那份）与 Codex 可作为子 agent 调用，走现有适配层；
  它们的审批请求桥接到 Min 的卡片（DeepSeek Harness 一律拒绝，Min 做得更好）；父会话只收最终报告。

## 4.9 检查点与回滚（宿主 + kernel）

- **两层**：编辑工具记录改前内容（精确、快）；每个用户回合前，宿主侧用 JGit 对工作区做影子仓库快照（只存树、支持非 git 项目、
  不碰用户自己的 `.git`），**覆盖 Bash 造成的改动**——CC 的检查点不覆盖 Bash，这是明确的超越点。
- **Rewind** 三种范围：代码 / 对话 / 两者；回滚前先对当前状态再拍一张，可反悔（Cline）。
- 对话回滚 = 在日志里追加「HEAD 移到 itemId」事件（会话是事件树，OpenHands），不删除任何历史。

## 4.10 可观测、测试与评测（testkit + cli）

- **请求快照测试**：把「模型实际收到的请求」渲染成带占位符的文本快照，并标出前缀从第几项开始分叉（Codex）。
  **任何提示词、工具描述、上下文装配的改动都必须更新快照**——一套测试同时守住提示回归、缓存稳定性、压缩 / 恢复语义。
- **SSE 录放**：真实供应商流录成夹具（脱敏），离线回放；现有 `tools/record_cli_frames.py` 的思路搬过来。
- **恢复混沌测试**：在事件流随机点杀进程 → 重启 → 续跑；断言不丢输入、副作用不重放、请求可从日志逐字节重建。
- **桌面评测**：`agent:cli` 在桌面跑任务集（按模型分列成功率、花费、时延、缓存命中），每个里程碑出一张表；与同模型的 CC / Codex 对比。
- **线上信号**（本机、不上报）：Keep Rate（改动一段时间后是否还在）、用户下一步是否贴报错、审批拒绝率、压缩次数。
- **追踪**：每回合一条本机 trace（模型请求、工具、hooks、审批、为何继续），会话页可展开查看。不接任何默认上报（OpenAI SDK 默认上报的教训）。
