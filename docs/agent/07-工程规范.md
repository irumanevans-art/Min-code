# 07 · 工程规范（agent/ 专用，在仓库 CLAUDE.md 总原则之上）

仓库 `CLAUDE.md` 的「可维护性（总原则）」全部适用。下面是内核额外的规矩，每条都对应一个调研里见过的坑。

## 边界

1. 模块依赖只按 02 §2 的表走；架构测试钉死，违反即红。内核模块不认识 Android，也不认识 `dev.min.code`。
2. 真实 IO（文件、进程、网络、时钟、随机数）只出现在宿主实现里。内核里要时间就拿 `Clock`，要 id 就拿 `Ids`——
   否则恢复测试没法复现。
3. 不做运行时插件发现、不做反射注册。新工具 / 新供应商在组合根里显式 `register(...)`，一眼能看到全部。
4. UI 只认 `:agent:protocol`。想让 UI 多看到一样东西，先改协议（带版本说明），不要让 UI 伸手进 kernel。

## 持久化与协议

5. 事件与协议字段**只加不改不删**；需要改语义就新增类型。旧版本永远可读；读到更新的主版本直接拒绝。
   每次变更在 `agent/store/FORMAT.md` 或 `agent/protocol/CHANGELOG.md` 追加一行。
6. 凡是「模型看得到的东西」都必须来自日志（DeepSeek Harness 的不变式）。任何绕过日志往请求里塞内容的代码都是 bug。
   有一个断言测试：从日志重建的请求 == 实际发出的请求。
7. 有副作用的工具：副作用之前必须已落盘 `ToolEffectPending`（fsync），落盘失败就不执行。

## 提示与缓存

8. 稳定前缀会话内逐字不变。要告诉模型「变了什么」，就在末尾追加一段，不许改写前面。
9. **任何提示词、工具描述、上下文装配的改动都必须更新请求快照测试**，并在 PR / 提交说明里写 token 代价与缓存影响；
   涉及行为的还要跑评测集（CC 就是被「未经评测的系统提示改动」伤过）。
10. 工具表会话内只追加、不重排、不删除；要禁用某个工具就用规则挡住并追加说明，不从表里拿掉（Manus / Codex）。

## 并发与取消

11. 会话状态只由该会话的 actor 修改；其他地方只读快照。
12. 禁止用 `runCatching` 包挂起调用（会吞取消）；用 `catchingNonCancellation {}`。清理放 `withContext(NonCancellable)`。
13. 改时序或并发必须有测试覆盖边界：超时、半路取消、进程被杀、重复命令（幂等键）、过期的 `expectedTurnId`。

## 安全

14. 安全底线（04 §4.4）不可被配置、模式、hooks、插件关闭。改它必须 [O] 审并附攻击用例。
15. 命令判定只有一套解析器。不许为了「快」再加一条正则旁路。
16. 凭证只在 Keystore → HTTP 头之间流动：不进 rootfs、环境变量、argv、日志、事件、错误信息、崩溃报告。有测试扫日志。
17. 本机监听端口只绑 127.0.0.1 + 随机 token + 校验 Origin。
18. 第三方可执行物一律进程外。

## 文档

19. 每个模块根目录一份 README，固定四节：**模型看到什么 / token 代价 / 缓存影响 / 已知限制**（DeepSeek Harness 每包都这么写，
    半年后接手的人靠它）。
20. 工具清单、事件类型清单、配置键清单由代码生成到 `docs/agent/generated/`，CI（或单测）校验生成物与代码一致，不手写维护。
21. 文件超过约 800 行就拆；循环体、编解码器、调度器这类核心类各自一个文件，别让任何一个长成 CC 的 1400 行循环。
